# 프론트엔드 현재 구현 상태

이 문서는 프론트 프로토타입과 MSW의 현재 동작을 설명한다. 목표 비즈니스 규칙은 [도메인 설계](../../domain-design.md), 목표 API와 이관 상태는 [API 컨벤션](../../convention/api-convention.md)을 정본으로 사용한다.

## 공개 지원서와 Draft

- 공개 지원서는 공고별 입력값, 선택 배역, 진행 단계와 사진 Blob을 IndexedDB에 저장한다.
- 실제 저장 결과에 따라 `저장 중`, `이 기기에 저장됨`, `저장 실패`를 표시하고 저장되지 않은 변경이 있을 때만 이탈을 경고한다.
- 같은 브라우저에서 새로고침, 공고 상세 왕복, 소셜 로그인 화면 왕복 후 Draft를 복원한다.
- 비로그인 배우가 지원서 작성·이어쓰기를 시작하면 로그인 후 프로필을 불러올지, 로그인 없이 작성할지 선택한다.
- 제출 성공 시 현재 브라우저의 해당 Draft를 삭제하고, 제출 지원서는 내 지원서에서 읽기 전용 스냅샷으로 표시한다.
- 내 지원서 목록은 현재 브라우저의 작성 중 Draft와 제출 완료 스냅샷을 구분하고, 선택한 배역 수·배역별 공개 전형 상태를 표시한다.
- `/apply/lookup`은 로그인 후 내 지원서로 이동하고, 최종 검토 화면은 인증 전 제출을 차단한다.

서버 Draft 동기화, 인증 계정 자동 연결, 다른 기기의 Draft 목록은 아직 구현하지 않았다. IndexedDB 사본은 서버나 기획사/제작사에 전송되지 않는다.

## 지원 양식·프로필·스냅샷

- 기본 정보와 nullable 추가 정보 8개를 분리했다. 키와 몸무게는 `HEIGHT`, `WEIGHT` 독립 필드며 공고가 수집하지 않은 값은 심사 읽기 모델에서 `null`이다.
- 사진 요구는 `{ 유형 설명, 요구 장수 }` 배열로 총 10장까지 검증한다. 각 사진을 특정 유형에 연결하는 저장 계약은 아직 없다.
- 영상 요구는 0개로 시작해 최대 5개까지 추가한다. 지원서와 제출 스냅샷은 요구 순서대로 YouTube 링크를 보관하고, 심사 상세는 요구 설명·메인 플레이어·크게 보기를 같이 바꾼다.
- 지원 안내와 커스텀 답변은 각각 최대 2,000자로 제한한다.
- 프로필은 사진 최대 20장, YouTube 영상 최대 10개를 탭으로 관리하고 추가·삭제·순서·대표 사진 변경을 MSW에 즉시 저장한다.
- 프로필은 공고별 커스텀 답변을 보관하지 않는다.

실제 파일 업로드와 영속 프로필 저장 API는 아직 구현하지 않았다.

## 공연·공고 작성과 관리

- 공연 포스터·도로명주소, 이름·설명만 갖는 공연 배역, 공고별 지원 조건·대표 이미지 스냅샷·상세 이미지·연습 장소·공연 기간·모집 기간·최대 5차 전형을 MSW에 반영했다.
- 공연 장소와 연습 장소는 같은 주소 검색·지도 UI를 사용한다. `NEXT_PUBLIC_KAKAO_MAP_APP_KEY`가 없으면 주소만 표시하고 좌표 검색과 지도는 렌더링하지 않는다.
- `/producers/performances`는 공연 카드 목록이고 카드를 선택하면 공연별 공고 관리로 이동한다. 공고 목록은 상태 필터·검색·공개 공고 보기·지원자 관리를 제공한다.
- 관리자 `지원자 관리`는 공고의 배역 수와 관계없이 배역별 지원 현황을 먼저 표시한다. 배우 공개 지원서는 단일 배역 공고에서 배역 선택을 생략한다.
- 공고 상태 타입은 작성 중·진행 예정·진행 중·접수 마감·전형 종료를 지원한다. 현재 공고 생성 API와 화면은 완성된 공고 등록만 제공한다.
- 공연·공고 추가 폼은 마지막 변경 600ms 뒤 IndexedDB에 자동 저장하고 다시 열 때 복원한다. 실제 생성 성공 뒤 삭제하며 서버 `DRAFT`나 다른 계정·기기에 동기화하지 않는다.

공연·공고 포스터는 현재 Data URL 목 저장이며 공고는 생성 시점의 공연 포스터를 독립 스냅샷으로 가진다.

## 심사

- 복수 배역 지원 UI와 `(지원서, 배역, 차수)` 심사 저장 키를 적용했다.
- 심사 보드는 검토 대기와 검토 완료를 구분하고, 검토 완료에서 합격·불합격·불참·기타를 필터링한다.
- 모든 차수에서 현재 결과·검색·상세 조건으로 보이는 지원자를 인쇄하거나 연락처로 모아볼 수 있다. 개별 선택이 있으면 연락처 모아보기만 선택 대상을 우선한다.

현재 심사 상태는 MSW 메모리에 있어 새로고침하면 시드 상태로 돌아간다.

## 인증과 MSW

- `/login`은 일반 진입에서 배우·기획사/제작사 유형을 선택한다. 배우는 카카오·네이버·Google, 기획사/제작사는 이메일·비밀번호로 진행한다.
- `/forgot-password`는 기획사/제작사의 이메일, 인증번호, 새 비밀번호 흐름을 제공하는 프론트 프로토타입이다.
- `/signup`은 기획사/제작사 전용이며 MSW에서 `PENDING` 세션을 만든다. `PENDING`은 정보 설정 외 관리자 화면에서 인증 안내와 카카오톡 문의를 표시한다.
- 지원서 문맥의 로그인은 공고·배역·`returnTo`를 유지하고 인증 성공 뒤 `prefill=1&resumeDraft=1`로 최종 검토 화면을 다시 연다. 인증 취소는 목 인증 상태를 만들지 않고 로컬 Draft만 복원한다.

배우 소셜 인증과 기획사/제작사 세션은 프론트 React 상태로만 유지되어 새로고침하면 사라진다. 실제 OAuth, 서버 세션, 인증 메일·문자, `PENDING → ACTIVE` 운영 전환은 아직 구현하지 않았다.

## API·저장 경계

기본 개발 환경은 MSW를 사용한다. 추가로 만든 데이터와 심사 상태는 브라우저 메모리에 있어 새로고침하면 초기화된다. 브라우저 API는 같은 origin의 `/api/**` 상대 경로를, 공개 공고 SSR·메타데이터는 `API_ORIGIN`을 사용한다.

프론트·MSW는 목표 정책을 확인할 UI와 시드를 제공하지만, 서버 Draft·인증·파일·제출·영속 저장 계약은 목표 [API 컨벤션](../../convention/api-convention.md)과 추가 도메인 결정 후 구현해야 한다.
