# 프론트엔드 현재 구현 상태

이 문서는 프론트 프로토타입과 MSW의 현재 동작을 설명한다. 목표 비즈니스 규칙은 [도메인 설계](../../domain-design.md), 목표 API와 이관 상태는 [API 컨벤션](../../convention/api-convention.md)을 정본으로 사용한다.

## 공개 지원서와 Draft

- 공개 지원서는 공고별 입력값, 선택 배역, 진행 단계와 사진 Blob을 IndexedDB에 저장한다.
- 실제 저장 결과에 따라 `저장 중`, `이 기기에 저장됨`, `저장 실패`를 표시하고 저장되지 않은 변경이 있을 때만 이탈을 경고한다.
- 같은 브라우저에서 새로고침, 공고 상세 왕복, 소셜 로그인 화면 왕복 후 Draft를 복원한다.
- 지원서 작성은 `/apply/{postingId}/write/basic`, `/additional`, `/media`, `/questions`, `/review`로 분리한다. 단계 이동 시 URL도 함께 바뀌므로 새로고침과 브라우저 앞·뒤 이동 후에도 접근 가능한 현재 단계를 유지한다.
- 비로그인 배우가 지원서 작성·이어쓰기를 시작하면 로그인 후 프로필을 불러올지, 로그인 없이 작성할지 선택한다.
- 제출 성공 시 현재 브라우저의 해당 Draft를 삭제하고, 제출 지원서는 내 지원서에서 읽기 전용 스냅샷으로 표시한다.
- 최종 제출 버튼을 누르면 제출 후에는 내용을 수정할 수 없다는 확인 다이얼로그를 표시하고, 사용자가 다시 확인한 뒤 제출한다.
- 내 지원서 목록은 현재 브라우저의 작성 중 Draft와 Backend의 제출 완료 스냅샷을 구분한다. 제출 완료 카드는
  공연·공고·기획사명, 포스터, 선택 배역과 제출 시각을 표시하고 상세는 제출 당시 기본·추가 정보, 질문, 사진,
  영상을 읽기 전용으로 표시한다. 전형 진행 상태 공개는 MVP 이후 범위다.
- 배우 홈은 조회 하나가 실패해도 나머지 영역을 보여 준다. 추천 공고 Backend API가 아직 없어 실제 API 모드에서는 추천 영역을 노출하지 않고, 목 검증 환경에서만 기존 목 계약으로 표시한다.
- 최종 검토 화면은 인증 전 제출을 차단한다. `/apply/lookup`의 조회 코드 기반 비로그인 열람은 이전 목 흐름으로
  남아 있으며, 인증된 내 지원서의 실제 목록·상세 API에는 수정 기능을 제공하지 않는다.

IndexedDB 사본은 서버나 기획사/제작사에 전송되지 않는다. 이는 인증 전 Draft를 브라우저에만 두는 목표 정책과 일치한다. Draft 복원 시 필수 동의와 `프로필에도 저장` 선택은 복원하지 않고 초기화한다.

## 지원 양식·프로필·스냅샷

- 기본 정보와 nullable 추가 정보 8개를 분리했다. 키와 몸무게는 `HEIGHT`, `WEIGHT` 독립 필드며 공고가 수집하지 않은 값은 심사 읽기 모델에서 `null`이다. 성별은 `여성·남성`, 군필 여부는 `군필·미필·해당 없음`만 선택하며 `응답하지 않음` 선택지는 제공하지 않는다.
- 사진 요구는 `{ 유형 설명, 요구 장수 }` 배열로 총 3장까지 검증한다. 지원서 UI는 요구 순서대로 사진 슬롯을 만들고, 로그인 배우는 각 슬롯에서 보관함 사진을 직접 고르거나 새 파일을 선택한다. 비로그인 배우에게도 보관함 선택을 동일하게 노출하되 클릭하면 Draft 유지와 로그인 후 사용 가능 여부를 다시 안내한다. 보관함 사진은 자동 첨부하지 않으며 선택 결과는 공고별 IndexedDB Draft에 저장한다.
- 지원서 사진 슬롯은 데스크톱에서 최대 3개를 한 행에 배치하고, 최종 검토의 사진은 원본 비율을 유지하는 확대 화면으로 확인할 수 있다.
- 지원서 화면에서는 로그인 여부와 관계없이 사진 보관함의 추가·수정·삭제를 제공하지 않는다. 보관함 관리는 로그인 후 프로필에서만 한다.
- UUID 공고의 실제 제출 계약은 사진 요구 ID와 파일 ID를 명시적으로 연결해 저장한다. 시드 공고의 MSW 제출만
  기존 화면 입력 모델을 실제 조회 계약으로 변환한다.
- 영상 요구는 0개로 시작해 최대 3개까지 추가한다. 지원서 작성 화면은 유효한 YouTube 링크를 입력하면 즉시 재생 미리보기와 새 창 열기를 제공한다. 지원서와 제출 스냅샷은 요구 순서대로 YouTube 링크를 보관하고, 심사 상세는 요구 설명·메인 플레이어·크게 보기를 같이 바꾼다.
- 최종 검토 화면의 SNS·외부 링크와 YouTube 링크는 `http/https` 링크로 새 창에서 연다. 프로토콜을 생략한 일반 도메인은 `https://`로 보정한다.
- 지원 안내와 커스텀 답변은 각각 최대 2,000자로 제한한다.
- 프로필은 사진 최대 3장, YouTube 영상 최대 10개를 탭으로 관리하고 추가·삭제·순서·대표 사진 변경을 MSW에 즉시 저장한다.
- 프로필은 공고별 커스텀 답변을 보관하지 않는다.
- 프로필 저장 안내와 동작은 이번 지원서의 기본·추가 정보만 다루고 사진·영상·커스텀 답변은 제외한다.
- UUID 공고의 최종 제출은 실제 `POST /api/v1/auditions/{auditionId}/submissions`를 호출한다. 새 사진은 제출 과정에서 배우 사진 API로 업로드·완료하고 공고의 requirement ID와 연결한다. UUID 공고는 로그인 배우의 현재 Backend 프로필과 공개 공고 양식을 Frontend에서 조합해 공고가 수집하는 기본·추가 정보만 자동으로 채운다. 기존 로컬 Draft가 있으면 Draft를 우선하며 사진·영상·커스텀 답변은 자동으로 넣지 않는다. 시드 공고는 기존 MSW prefill·제출 흐름을 유지한다.
- 지원서 제출에서 프로필 저장을 선택하면 제출 성공 후 현재 프로필과 병합해 `PATCH /api/v1/applicants/me/profile`을 호출한다. 값을 입력한 수집 필드만 덮어쓰고, 저장 실패는 제출 성공에 영향을 주지 않으며 완료 화면에서 안내한다. 시드 공고는 기존 MSW 제출 흐름이 목 프로필을 함께 갱신한다.
- 최종 검토는 개인정보 수집·이용과 제3자 제공을 각각 필수 체크박스로 받고, 상단의 전체 동의로 두 값을 함께 바꿀 수 있다. UUID 공고 제출은 두 동의 값을 Backend 요청에 각각 전달한다.
- 연락처 입력은 숫자만 받아 최대 11자리 `000-0000-0000` 형태로 표시한다. 키·몸무게의 정수 제한, 미래 생년월일 차단, 모집 마감일 기준 만 나이 계산과 만 14세 미만 제출 차단은 아직 없다.
- 학력은 단일 문자열이고 경력 최대 10개는 적용되어 있다. 링크는 단일 입력이며 최대 5개 반복 입력과 추가 질문 최대 10개 제한은 없다.

Backend에는 실제 파일 업로드·사진 보관함, 영속 프로필 기본·추가정보와 YouTube 영상 보관함 API가
구현됐다. `NEXT_PUBLIC_API_MOCKING=enabled`이고 `NEXT_PUBLIC_APPLICANT_PROFILE_API`가 비활성일 때만
Frontend 프로필 화면이 `/api/**` 목 계약과 브라우저 Blob URL을 사용한다.
`NEXT_PUBLIC_APPLICANT_PROFILE_API=enabled` 또는 MSW를 활성화하지 않은 실제 API 모드에서는
프로필 정보·사진·영상을 각각의 `/api/v1/**` Backend API에 연결한다. 전용
`GET /api/v1/applicants/me/profile/prefill` Backend API는 아직 없으며, 현재 MVP 자동 채움은 기존 프로필
조회와 공개 공고 양식을 Frontend에서 교집합으로 변환한다.

## 공연·공고 작성과 관리

- 공고 추가 모달은 저장 실패 시 오류가 발생한 구간으로 스크롤한다. 실제 Backend 오류 코드와 항목 검증 실패의 필드 경로를 모두 구간에 대응시킨다.

- 공연 포스터·도로명주소, 이름·설명만 갖는 공연 배역, 공고별 지원 조건·대표 이미지 스냅샷·상세 이미지·연습 장소·공연 기간·모집 기간·최대 5차 전형을 MSW에 반영했다.
- 공연 장소와 연습 장소는 같은 주소 검색·지도 UI를 사용한다. `NEXT_PUBLIC_KAKAO_MAP_APP_KEY`가 없으면 주소만 표시하고 좌표 검색과 지도는 렌더링하지 않는다.
- `/producers/performances`는 공연 카드 목록이고 카드를 선택하면 공연별 공고 관리로 이동한다. 공고 목록은 상태 필터·검색·공개 공고 보기·지원자 관리를 제공하며, 데스크톱에서는 지원 링크 복사를 카드에서 바로 실행하고 모바일에서는 더보기 메뉴에 유지한다.
- 공연 수정 모달은 `GET /api/v1/performances/{performanceId}`로 기존 장소·포스터·배역을 채운다. 배역은 읽기 전용이며, 새 포스터가 있으면 직접 업로드를 완료한 뒤 `PUT /api/v1/performances/{performanceId}`로 포스터·공연명·장소만 저장한다.
- 관리자 `지원자 관리`는 공고의 배역 수와 관계없이 배역별 지원 현황을 먼저 표시한다. 배우 공개 지원서는 단일 배역 공고에서 배역 선택을 생략한다.
- 공고 상태 타입은 작성 중·진행 예정·진행 중·접수 마감·전형 종료를 지원한다. 현재 공고 생성 API와 화면은 완성된 공고 등록만 제공한다.
- 공고 수정 화면은 진행 중에도 공연 일정·전형 일정을 보여 주고 수정할 수 있다. 모집 종료 연장은 목표 정책과 일치하지만, 목표 정책은 진행 중에 공고명과 모집 종료 연장만 허용하고 마감 뒤에는 모든 수정을 막는다.
- 공연·공고 추가 폼은 마지막 변경 600ms 뒤 IndexedDB에 자동 저장하고 다시 열 때 복원한다. 실제 생성 성공 뒤 삭제하며 서버 `DRAFT`나 다른 계정·기기에 동기화하지 않는다.

공연·공고 포스터는 현재 Data URL 목 저장이며 공고는 생성 시점의 공연 포스터를 독립 스냅샷으로 가진다.

## 심사

- 복수 배역 지원 UI와 `(지원서, 배역, 차수)` 심사 저장 키를 적용했다.
- 심사 보드는 검토 대기와 검토 완료를 구분하고, 검토 완료에서 합격·불합격·불참·기타를 필터링한다.
- 심사 상세의 차수별 기록은 해당 공고에 실제 등록된 전형 차수까지만 표시한다.
- 모든 차수에서 현재 결과·검색·상세 조건으로 보이는 지원자를 인쇄하거나 연락처로 모아볼 수 있다. 개별 선택이 있으면 연락처 모아보기만 선택 대상을 우선한다.

숫자형 실제 배역 ID는 Backend의 심사 목록·UUID 상세·결과 저장 API를 사용한다. seed 배역은 MSW 메모리를
사용하므로 새로고침하면 시드 상태로 돌아간다. 실제 지원서의 미수집 값은 `미수집`으로 표시하고 추가 질문은
지원서 스냅샷의 질문·답변 목록을 그대로 표시한다.

## 인증과 MSW

- `/login`은 일반 진입에서 배우·기획사/제작사 유형을 선택한다. 배우는 카카오·네이버·Google, 기획사/제작사는 이메일·비밀번호로 진행한다.
- `/forgot-password`는 기획사/제작사의 이메일, 인증번호, 새 비밀번호 흐름을 제공하는 프론트 프로토타입이다.
- `/signup`은 기획사/제작사 전용이며 가입 직후 `ACTIVE` 세션으로 자동 로그인해 공연 관리 화면으로 이동한다. 향후 기획사 인증 도입을 위한 `PENDING` 접근 제한과 안내 컴포넌트는 보존하지만 현재 가입 흐름에서는 사용하지 않는다.
- 지원서 문맥의 로그인은 공고·배역·`returnTo`를 유지하고 인증 성공 뒤 `prefill=1&resumeDraft=1`로 최종 검토 화면을 다시 연다. 사진 업로드나 최종 제출에서 Backend가 `401`을 반환하면 만료된 프론트 로그인 상태를 전체 페이지 이동으로 초기화하고 같은 로그인 복귀 경로를 사용한다. 실제 Backend에 제출하는 UUID 공고는 MSW 환경에서도 실제 소셜 로그인으로 Backend Session을 만든다. 인증 취소는 목 인증 상태를 만들지 않고 로컬 Draft만 복원한다.
- 동일 이메일의 소셜 가입 안내·명시적 계정 연결, 배우와 기획사/제작사 계정의 서버 수준 분리, 약관 버전·동의 시각 저장, 만 14세 제출 차단은 구현하지 않았다.

`NEXT_PUBLIC_PRODUCER_LOGIN=enabled`이면 기획사/제작사의 가입·로그인·현재 세션 확인·로그아웃 요청을
실제 `/api/v1/producers`, `/api/v1/sessions` API로 전달한다. `NEXT_PUBLIC_PRODUCER_API=enabled`도 함께 설정하면
공연 목록과 공연·공고 생성 등 구현 완료된 `/api/v1/**` 기획사 API를 실제 서버로 전달한다. 기획사 정보와
같이 아직 API가 없는 조회만 MSW가 계속 처리한다. 공연·공고 관리 목록과 탐색 트리는 실제 Backend를 사용한다.
가입 성공 시 같은 이메일·비밀번호로 즉시 로그인한다. 백엔드가 반환한 회원 ID·역할·상태로 프론트 인증 상태를 만들고, 새로고침할 때도
HttpSession을 조회해 복원한다.

`NEXT_PUBLIC_SOCIAL_LOGIN=enabled`이거나 MSW를 활성화하지 않은 실제 API 모드이면 배우 소셜 로그인 버튼은 같은 origin의
`/oauth2/authorization/{provider}`로 이동하고, Next.js가 OAuth 시작·Callback 요청을 백엔드에
전달한다. MSW 목 환경의 배우 소셜 인증은 프론트 React 상태로만 유지되어 새로고침하면
사라진다. 실제 소셜 로그인 환경에서는 앱을 시작할 때 `GET /api/v1/sessions/current`로 HttpSession을
확인하고 프론트 인증 상태를 복원한다. 실제 세션이 없거나 배우 계정이 아니면 `/applicants/**`에서
`/login`으로 이동한다. 실제 환경의 로그아웃은 `DELETE /api/v1/sessions/current` 성공 후 프론트
인증 상태를 제거한다. 실제 소셜 로그인 전 안전한 내부 `returnTo`를 탭의 `sessionStorage`에 보관하고,
`/social-login/complete`에서 세션 확인 후 해당 화면으로 복귀한다. MSW 목 환경은 시나리오 확인을
위해 직접 접근을 유지한다. 인증 메일·문자와 `PENDING → ACTIVE` 운영 전환은 MVP 이후 도입하며, 현재 기획사/제작사 가입은 즉시 `ACTIVE`로 처리한다.

`NEXT_PUBLIC_APPLICANT_PROFILE_API=enabled`이거나 MSW를 활성화하지 않은 실제 API 모드이면 배우 프로필 화면은
기본·추가 정보를 `/api/v1/applicants/me/profile`, 사진을 `/api/v1/applicants/me/photo-library/photos`,
영상을 `/api/v1/applicants/me/video-library/videos`에서 각각 조회해 하나의 화면 모델로 조합한다.
사진 추가는 `/api/v1/actor-photos/upload-requests`로 받은 presigned URL에 업로드하고 완료 처리한 뒤
사진 보관함에 연결한다. 사진 순서 이동과 대표 사진 지정도 각각의 사진 보관함 API로 즉시 저장한다.
플래그가 없으면 기존 `/api/me/profile` MSW 시나리오를 유지한다.

## API·저장 경계

기본 환경은 실제 API를 사용한다. `NEXT_PUBLIC_API_MOCKING=enabled`인 목 검증 환경에서 만든 데이터와 심사 결과·전형 종료 상태는 브라우저 메모리에 있어 새로고침하면 초기화된다. 브라우저 API는 같은 origin의 `/api/**` 상대 경로를, 공개 공고 SSR·메타데이터는 `API_ORIGIN`을 사용한다.

프론트·MSW는 목표 정책을 확인할 UI와 시드를 제공한다. 배우 프로필 정보·사진·영상은 플래그로 실제 API를
검증할 수 있고, UUID 공고의 새 사진 업로드와 지원서 제출도 실제 Backend 계약에 연결됐다. 나머지 배우
API와 영속 저장 계약은 목표 [API 컨벤션](../../convention/api-convention.md)과 추가 도메인 결정 후 구현해야
한다. 인증 전 서버 Draft는 목표 범위가 아니다.
