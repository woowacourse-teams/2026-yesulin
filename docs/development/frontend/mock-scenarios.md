# MSW 시나리오와 UI 검증 기준

MSW 목 데이터는 단순 예시가 아니라 프론트엔드 동작과 향후 백엔드 계약을 검증하는 실행 가능한 명세다. 개발 환경의 `/dev/scenarios`에서 대표 상태를 URL로 바로 열 수 있다.

## 지원 양식

| 시나리오 | 경로 | 검증 기준 |
| --- | --- | --- |
| 기본 복수 배역 | `/apply/seed_posting_1` | 배역 복수 선택, 기본·추가·사진·영상·질문 단계. 로그인 시 프로필·전신 사진 슬롯에서 보관함 사진을 각각 직접 선택하고 새 사진으로 교체 가능. YouTube 링크 입력 시 요구 항목별 재생 미리보기 표시 |
| 최소 기본정보 | `/apply/seed_posting_minimal` | 단일 배역과 빈 섹션 생략, 이름·연락처·이메일만 노출 |
| 키 미수집 | `/apply/seed_posting_without_height` | `HEIGHT` 미노출, `WEIGHT` 필수 노출, 사진 단계 유지 |
| 전체 항목 | `/apply/seed_posting_all_fields` | 기본정보 8개, 전체 추가정보, 추가 질문 3개와 긴 화면 |

키와 몸무게는 각각 `HEIGHT`, `WEIGHT` 답변으로 전달한다. 공고가 수집하지 않은 값은 심사 읽기 모델에서 `null`이며 화면에는 `미수집`으로 표시한다.

성별과 군필 여부에는 `응답하지 않음` 선택지를 표시하지 않는다. 최종 검토 화면에서 프로토콜을 생략한 SNS·외부 링크와 YouTube 요약 링크를 선택하면 각각 안전한 `https` 새 창으로 열려야 한다.

사진 보관함은 지원서 진입 시 자동 첨부하지 않는다. 로그인 전에도 항목별 `보관함에서 선택`을 동일하게 표시하고 클릭하면 로그인 후 사용 가능하며 현재 Draft가 유지된다는 안내를 제공한다. 로그인한 배우는 보관함 사진을 선택할 수 있고, 로그인 여부와 관계없이 새 사진 파일도 선택할 수 있다. 지원서 안에서는 사진 보관함 추가·수정·삭제를 제공하지 않는다. 선택한 보관함 사진과 새 사진은 해당 공고의 로컬 Draft를 다시 열었을 때 같은 슬롯에 복원되어야 한다.

## 심사 흐름

| 시나리오 | 경로 | 초기 상태와 검증 기준 |
| --- | --- | --- |
| 단일 배역 지원 현황 | `/producers/postings/seed_posting_round_2` | 배역 1개도 배역별 지원 현황을 표시하고 선택 후 심사 보드 이동 |
| 1차 진행 | `/producers/roles/seed_role_seoyeon?round=1` | 2차 잠김, 1차 불참 선택 불가 |
| 최대 영상 심사 | `/producers/roles/seed_role_seoyeon/applications/26081201?round=1` | 공고 상한인 영상 5개와 요구 설명 표시, 목록 스크롤 및 선택 시 제목·메인 플레이어·새 창·크게 보기 대상 동기화 |
| 2차 진행 | `/producers/roles/seed_role_round_2?round=2` | 1차 마감, 1차 합격자 3명 승계, 2차 일부 검토 완료 |
| 3차 진행 | `/producers/roles/seed_role_round_3?round=3` | 1·2차 마감, 2차 합격자 3명 승계, 3차 일부 검토 완료 |

심사 초기 상태는 `(지원서, 배역, 차수)` 결과와 `(배역, 차수)` 마감 상태를 별도로 시드한다. 화면에서 변경한 인메모리 상태는 새로고침하면 해당 프리셋으로 돌아간다.

## 공통 Visual QA

- 모바일 390×844와 데스크톱 1440×1000에서 가로 overflow가 없어야 한다.
- sticky header와 하단 action이 입력 또는 목록 내용을 가리지 않아야 한다.
- 키보드만으로 시나리오 카드, 단계 이동, 심사 필터와 결과 버튼을 사용할 수 있어야 한다.
- 필수·선택·잠김·마감·검토 대기 상태는 색상만이 아니라 텍스트로 구분되어야 한다.
- 긴 공고명, 질문, 지원자 정보가 레이아웃을 밀어내지 않아야 한다.
- 로딩·빈 상태·오류 상태의 접근 가능한 이름과 재시도 안내를 유지한다.

## 백엔드 계약으로 넘길 항목

- 지원 양식 필드 배열과 `HEIGHT`·`WEIGHT` 독립 답변
- 1~5차 전형 설정과 이전 차수 마감 전 다음 차수 잠금
- 심사 결과의 `(applicationId, roleId, round)` 식별
- 차수 마감의 `(roleId, round)` 식별과 검토 대기·대상 없음 오류
- 미수집 개인정보의 `null` 표현과 필터 처리
