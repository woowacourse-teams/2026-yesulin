# 커뮤니티 로그인 참여·작성자 공개 방식 요구사항

작성일: 2026-11-04
상태: 기능 구현·로컬 검증 완료. 운영 배포·실제 소셜 로그인 왕복은 별도 확인이 남아 있다.

누구나 대화를 읽고, 로그인한 배우는 익명 또는 프로필 공개로 참여한다.
부담 없이 고민을 나누는 참여와 자신을 소개하며 동료를 찾는 참여를 한 게시판에서 지원한다.
로그인은 작성물의 소유 확인 수단이며, 실명·배우 신원 인증을 뜻하지 않는다.

현재 동작은 [공통 도메인](domain.md#익명-커뮤니티)과 코드가 기준이다.
[기존 체크리스트](community-requirements.md)의 C01~C11 완료 표시는 이전 비회원 구현의 기록이며,
이 문서의 로그인 전환 완료를 뜻하지 않는다. 운영 정책 적용은 배포 이후다.

## 1 확정한 기능 방향

| 항목 | 목표 동작 |
| --- | --- |
| 읽기 | 최신 5개와 상세·댓글·공유 링크 공개. 이전 글 목록은 로그인 후 열람 |
| 새 글·댓글 | 활성 배우 계정으로 로그인 후 작성. 제작사·관리자 계정은 읽기만 가능 |
| 작성자 표시 | 익명 또는 프로필 공개 선택. 실명 공개라는 표현은 사용하지 않음 |
| 익명 | 다른 이용자에게 계정·프로필을 연결하지 않음. 익명 번호는 글 안에서 유지 |
| 프로필 공개 | 공개할 이름과 정보를 작성 전에 확인. 비공개 프로필 전체를 자동 공개하지 않음 |
| 작성물 관리 | 새 작성물은 계정 소유. 같은 계정이면 다른 브라우저에서도 수정·삭제 |
| 기존 작성물 | 기존 브라우저 소유 확인과 수정·삭제 권한 유지. 자동 계정 귀속·공개 전환 금지 |
| 게시판 | 기존 단일 피드·자유 주제 유지. 별도 익명/공개 게시판으로 분리하지 않음 |
| 기존 기능 | 좋아요는 브라우저당 한 번·취소, 신고는 비회원 가능이라는 현행 정책 유지 |

프로필 완성·경력 입력을 익명 작성의 전제 조건으로 추가하지 않는다.
익명은 이용자 사이의 표시 방식이며, 서버가 작성 계정을 전혀 알 수 없다는 뜻이 아니다.

## 2 화면과 참여 흐름

### 읽기 → 로그인 → 작성

1. 비로그인 이용자는 목록·글·댓글을 바로 읽는다.
2. 글쓰기 또는 댓글 작성 동작을 선택하면 기존 로그인 화면으로 연결한다.
3. 로그인 성공 후 원래 글쓰기 화면 또는 해당 글의 댓글 작성 위치로 돌아온다.
4. 익명/프로필 공개 선택과 실제 표시될 작성자를 확인한 뒤 등록한다.
5. 서버 저장 성공 후 글 상세로 이동하거나 댓글 목록을 갱신한다.

로그인 취소·실패는 공개 열람을 막지 않는다. 로그인 복귀 주소는 서비스 내부의 허용 경로만 사용한다.
작성 중 세션이 만료되면 입력을 보존하고 재로그인을 안내한다. 복귀만으로 자동 게시하지 않는다.
계정 변경 후에는 이전 계정의 초안·공개 방식·수정 권한을 자동 적용하지 않는다.
초안 복구의 계정 확인·저장 위치·보존기간은 아래 M01 설계를 따르고, 내용·토큰을 URL이나 분석 이벤트에 넣지 않는다.

### 작성자 선택과 표시

- 기본은 익명이며 글·댓글마다 다시 선택할 수 있다. 기존 작성물의 공개 방식은 유지된다. 글쓰기 폼은 프로필 미리보기를 생략한다.
- 글과 같은 방식으로 참여한 작성자에게만 글쓴이 표시를 붙인다.
- 익명 작성자는 같은 계정으로 기기를 바꿔도 같은 글에서 번호를 유지한다.
  다른 글과 연결되는 공개 식별자·아바타·프로필 링크를 제공하지 않는다.
- 서로 다른 글의 공개 활동과 익명 활동을 공개 프로필에서 연결하지 않는다.
  공개 작성 목록을 나중에 만들더라도 익명 작성물은 포함하지 않는다.
- 이름·사진 변경만으로 과거 익명 글이 공개되거나 표시 방식이 바뀌지 않는다.

2026-11-04 사용자 확정 정책:

- P01: 기존 공개 배우 페이지의 이름·공개 대표 사진·페이지 링크만 사용한다. 별도 커뮤니티 프로필은 만들지 않는다.
  공개 페이지가 없어도 익명 참여는 가능하다. 소셜 이름·사진은 자동 공개하지 않는다.
- P02: 활성 배우(APPLICANT + ACTIVE)만 새 글·댓글을 작성한다. 제작사·관리자는 읽기만 가능하며 기존 비회원 관리 권한은 별개다.
- P03: 공개 여부와 무관한 전체 첫 참여 순서로 번호를 배정한다. 익명1 → 공개 이름 → 익명3처럼 번호가 건너뛰어도 유지한다.
- P04: 과거 공개 작성물도 현재 공개 프로필을 반영한다. 비공개·잠금·공개 조건 미충족 시 이름·사진·링크를 제거하고
  `프로필 비공개`로 표시한다. 다시 공개하면 현재 정보를 표시한다. 계정이 없으면 `알 수 없는 사용자`다.
  표시 모드 자체는 바꾸지 않고 익명 글은 계속 익명으로 유지한다. 탈퇴 기능은 이번 범위에 추가하지 않는다.

2026-11-05부터 한 글에서 익명과 공개를 따로 선택할 수 있다. 각 모드의 첫 참여가 별도 번호를 차지한다. 기존 브라우저 참여와 새 계정 참여를 동일인이라고 자동 병합하지 않는다.

### UI 유지 기준

- 기존 예술in 로고·공통 상단바·밝은 색감을 유지한다.
- 작성 모드는 `익명` / `배우 프로필 공개`로 표시하고 아이콘만으로 구분하지 않는다.
- 불필요한 부가 설명은 피드에 반복하지 않는다. 필요한 오류·선택 확인은 해당 동작에만 표시한다.
- 댓글 목록을 먼저, 입력 영역을 아래에 둔다. 댓글 등록 후 이미 읽은 댓글을 새 댓글 하나로 교체하지 않는다.
- 댓글은 기존 페이지 단위 조회를 활용하되 더 보기를 통해 전체를 읽을 수 있어야 한다.
  새 댓글 등록 시 기존 목록·중간의 미조회 구간을 잃지 않고, 순서와 중복 없이 새 댓글을 확인할 수 있게 한다.

### 피드와 댓글 알림 (#531)

- [x] 최신 5개 공개, 로그인 복귀 후 5개씩 더보기
- [x] 좋아요 10개 이상 인기 표시, 카드 여백에서 상세 이동
- [x] 글 안에서 참여자를 익명과 숫자로 구분, 댓글과 대댓글별 익명 체크
- [x] 받은 댓글은 공통 헤더의 알림 종(배우 계정)에서 최근 5묶음을 펼쳐 보고, 전체는 커뮤니티 알림 화면(`/community/notifications`)에서 본다. 같은 글·같은 종류·같은 읽음 상태 알림은 "익명2 외 1명이"처럼 한 줄로 묶고, 작성자 이름·시각·댓글 미리보기를 보인다. 누르면 묶인 알림을 읽음 처리하고 가장 최근 댓글로 이동하며, 모두 읽음을 지원한다. 종에는 읽지 않은 수를 표시한다. 예전 마이페이지 받은 댓글 주소는 알림 화면으로 보낸다(2026-11-05 변경).

## 3 권한·데이터 전환 요구사항

### 신규 계정 작성물

- 소유 계정은 요청 본문이 아닌 서버 세션에서 결정한다. 익명 여부는 소유권과 별도로 저장한다.
- 새 글·댓글 생성은 비로그인·만료 세션에서 거절한다. 기존 공개 쓰기 경로로 우회할 수 없어야 한다.
- 로그인만으로 다른 사람의 글·댓글 수정·삭제 권한이 생기지 않는다. 기존 브라우저 쿠키도 새 계정 작성물의 권한을 대신하지 않는다.
- 같은 생성 요청 재전송은 원래 계정·대상·내용·표시 방식이 같을 때만 기존 결과를 반환한다.
  다른 계정 또는 다른 내용·표시 방식으로 재사용한 요청은 충돌로 처리한다.
- 동일 계정의 동시 첫 댓글은 참여자 기록·익명 번호를 중복 생성하지 않는다.
  서로 다른 요청 번호라면 익명과 프로필 공개 댓글을 각각 등록한다. 같은 요청 번호로 방식을 바꿔 재시도하면 충돌로 처리한다.
- 댓글 삭제·재작성·페이지 이동으로 다른 참여자의 번호를 바꾸거나 기존 번호를 재사용하지 않는다.
- 삭제된 글에는 새 댓글을 받지 않고, 글 삭제·댓글 생성 경합에서도 공개 댓글 수가 어긋나지 않아야 한다.
- 공개 API·HTML·초기 렌더링 데이터에 익명 계정 ID, 해시, 소셜 정보, 비공개 프로필 정보를 넣지 않는다.
  공개 모드도 허용된 공개 필드만 반환한다. 화면에서 숨기는 것만으로 보호했다고 보지 않는다.

### 기존 비회원 작성물

- 기존 게시글·댓글·URL·내용·익명 번호·삭제 상태·좋아요·신고 이력을 보존한다.
- 기존 HttpOnly 쿠키 및 이미 지원하는 과거 키 이전 흐름으로 수정·삭제할 수 있다.
  **기존 작성물 관리에는 로그인 강제를 추가하지 않는다.** 신규 작성 인증과 분리된 호환 경로다.
- 같은 브라우저에서 로그인했다고 과거 글을 그 계정에 자동 귀속하지 않는다.
  공유 브라우저일 수 있으므로 쿠키 소유와 계정 소유를 구분한다.
- 과거 글을 계정에 가져오는 기능은 이번 범위 밖이다. 추후 소유 증명·사용자 선택·충돌 정책을 먼저 정한다.
- 기존 쿠키를 잃은 작성물의 권한을 로그인만으로 복구한다고 안내하지 않는다.
- DB 변경은 기존 행을 보존하는 추가 방식으로 준비하고, 전환 시점·적용 순서·되돌리기 한계를 기록한다.
  새 회원 글을 구버전 코드가 브라우저 글로 잘못 취급하거나 읽기 실패하지 않는지 확인한다.

## 4 구현 체크리스트

각 항목은 관련 테스트·실제 요청/UI 확인이 끝난 뒤 `[x]`로 바꾼다.
문서 작성 완료나 코드 작성만으로 체크하지 않는다. 정책 확정과 구현 완료는 별도로 표시한다.

### M01 계약·정책과 이행 설계

- [x] P01~P04 사용자 확정을 반영한다(2026-11-04).
- [x] 기존 세션·회원 역할·공개 프로필 계약을 확인하고 재사용 범위를 정한다.
- [x] 계정 소유와 기존 브라우저 소유, 글별 참여·표시 방식의 저장 모델을 설계한다.
- [x] 생성·조회·수정·삭제의 인증 조건, 공개 필드, 오류 및 재시도 계약을 설계한다.
- [x] 로그인 왕복·만료·계정 변경 시 초안 보존/분리/정리 기준을 정한다.
- [x] 기존 DB의 이행·호환·복구 절차와 검증용 기존 데이터 표본을 준비한다.

완료 기준: 현행 쓰기 경로의 우회가 없고, 신규 작성 인증과 기존 관리 권한이 구분된 설계가 있다.
구현·실제 요청 검증 전에는 동작 완료로 처리하지 않는다.

### M02 회원 소유와 로그인 작성

- [x] 기존 행을 보존하면서 계정 작성물·참여자 모델을 추가한다.
- [x] 새 글·댓글 생성에 세션 인증과 확정된 계정 자격을 적용한다.
- [x] 다른 기기의 동일 계정은 수정·삭제 가능하고 다른 계정·비로그인은 거절한다.
- [x] 계정/대상/내용/표시 방식이 포함된 생성 재시도·충돌을 검증한다.
- [x] 세션 만료·CSRF 누락·변조 계정 ID·삭제 대상·동시 댓글의 실패 경계를 검증한다.

### M03 익명 참여

- [x] 작성물마다 모드를 선택하고 익명 활동을 공개 프로필과 연결하지 않는다.
- [x] 확정한 혼합 참여 번호 규칙과 기기 간 동일 계정 번호 유지를 구현한다.
- [x] 동시 첫 참여·삭제·재작성·페이지 조회에서 참여자·번호가 안정적인지 검증한다.
- [x] 공개 API·HTML·프로필 조회에 익명 작성자의 계정·공개 프로필 연결 정보가 없는지 검증한다.

### M04 프로필 공개 참여

- [x] P01에서 정한 공개 이름·사진·링크 원천과 공개 가능 조건을 적용한다.
- [x] 공개할 정보가 없거나 조건을 충족하지 못하면 익명 참여는 계속 허용하고 공개 모드만 필요한 입력으로 안내한다.
- [x] 등록 전 공개될 작성자 정보를 보여 주고, 등록 직전 서버에서 공개 가능 상태를 확인한다.
- [x] 이름 변경·사진 삭제·프로필 비공개/잠금·계정 상태 변화 시 확정한 표시 정책을 적용한다.
- [x] 비공개 사진·연락처·이메일·공연사 전용 자료가 응답과 캐시에 노출되지 않는지 검증한다.
- [x] 익명 글은 공개 프로필 연결·작성 목록·공유 미리보기에서 식별되지 않게 한다.

### M05 로그인 복귀·작성 UI

- [x] 공개 읽기를 유지하면서 글·댓글 작성 진입에서 로그인을 연결한다.
- [x] 로그인 복귀 경로가 기존 인증 계약을 통과하고 원래 글/댓글 작성·수정 위치를 열도록 한다. 취소·실패에도 공개 읽기를 유지한다(자동 테스트·로컬 화면 확인).
- [x] 만료 세션의 초안을 보존하고 재로그인 후 확인을 거쳐 재시도한다. 자동 게시하지 않는다.
- [x] 로그아웃·계정 변경·늦은 응답에서 이전 계정의 초안·권한·프로필 표시를 섞지 않는다.
- [x] 글·댓글별 익명 체크를 제공하고 글쓰기에서 프로필 미리보기를 생략한다.
- [x] 댓글 목록 아래에 입력창을 두고 등록 후 기존 댓글과 새 댓글을 순서·중복 없이 확인한다.
- [x] 모바일·데스크톱·키보드에서 기존 헤더·로고·색감과 로딩·실패·재시도 동작을 확인한다.

### M06 기존 글 권한과 회귀 검증

- [x] 전환 이전 글·댓글의 내용·번호·URL·삭제 상태와 쿠키 소유자의 수정·삭제가 유지된다.
- [x] 기존 글은 유효한 소유 쿠키가 있으면 로그인 여부·현재 계정과 무관하게 관리한다. 쿠키 누락·불일치는 로그인만으로 대체하지 못하며 자동 계정 귀속도 없다.
- [x] 과거 키→HttpOnly 이전의 실패·재시도·충돌 시 기존 권한을 잃지 않는다.
- [x] 기존 글에 새 계정이 댓글을 써도 과거 번호를 바꾸거나 계정을 추정해 병합하지 않는다.
- [x] 비회원 좋아요·취소·신고 및 최초 신고 알림 기록·재시도가 유지된다.
- [x] 신규 작성물은 쿠키가 같아도 다른 계정에서 관리할 수 없다.

### M07 측정·계약·출시 확인

- [x] 구현된 정책만 domain/API/도메인 작업 규칙에 반영하고 미구현 목록을 갱신한다.
- [x] 변경 영역 테스트·필수 검사, 실제 인증 요청과 공개 읽기/쓰기 UI를 확인한다.
- [x] 기존 데이터가 있는 로컬 H2 사본에서 이행과 백업 사본 기동을 확인한다.

- [x] 독립 평가·발견 문제 수정·표적 재검증을 기록한 뒤 기능별 완료 표시와 커밋을 남긴다.

## 5 개발 순서와 완료 기준

M01 → M02 → M03·M04 → M05 → M06 → M07 순서로 진행한다.
M06의 기존 데이터 보존 테스트는 M02부터 함께 실행한다. 익명/공개가 모두 검증되기 전에는 전환 완료로 배포하지 않는다.

각 작은 동작마다 실패 테스트(Red) → 최소 구현(Green) → 정리(Refactor) → 관련 검사 → 체크 → 커밋으로 진행한다.
백엔드 domain/application 규칙을 자동 테스트하고 Controller·외부 연동은 저장소 지침에 따라 실제 요청으로 검증한다.
프론트는 인증 복귀·초안·응답 갱신 같은 로직을 검증하며 문구만 따라 쓰는 테스트는 만들지 않는다.
신규 코드에 else·삼항·주석을 추가하지 않고 작은 메서드·낮은 중첩·현재 규모에 맞는 책임 분리를 적용한다.

구현 완료는 사용자 시나리오, 실패·동시성·권한 경계와 기존 데이터 보존을 확인한 상태다.
커밋·push·병합·배포는 각각 별개이며 이 문서 작성으로 실행되지 않는다.

## 8 M01 최초 구현 기록 (2026-11-04 기준)

- 이슈: [#506](https://github.com/woowacourse-teams/2026-yesulin/issues/506). 브랜치: `feat/community-member-participation`.
- 기존 `community_entries`에 nullable 회원 ID와 기본 익명 표시 모드를 추가한다. 기존 owner hash는 변경하지 않는다.
  회원의 내부 참여 키는 `member:` 접두사로 쿠키 해시와 구분한다. 공개 응답에는 내보내지 않는다.
- 기존 글별 첫 참여 순서 조회와 글 행 잠금을 재사용한다. 별도 참여자 테이블 없이 삭제된 댓글까지 포함해 모드를 고정한다.
- 새 POST는 배우 세션을 요구한다. 조회/기존 PUT·DELETE는 선택 세션과 쿠키를 받아 저장된 소유 유형에 맞춰 확인한다.
  CSRF는 그대로 유지한다. 잘못된 역할은 403, 세션 없음은 401, 표시 방식·재시도 충돌은 409다.
- 공개 응답은 작성자 이름·공개 사진·배우 페이지 경로·글쓴이 여부를 추가한다. 회원 ID는 작성자의 공개 응답에 넣지 않는다.
  본인 참여 상태는 별도 no-store 응답에서 로그인 자격·고정 모드·공개 미리보기만 확인한다.
- 새 글·새 댓글·회원 글/댓글 수정 초안은 같은 탭 sessionStorage에 계정과 작성물별로 분리한다.
  복구 유효시간은 마지막 저장 후 30분이며 다음 조회 때 만료 항목을 제거한다. 성공·취소·명시적 로그아웃 시 삭제한다.
  만료 재로그인 후 같은 계정만 복구하며 다른 계정은 이전 내용을 표시하거나 자동 게시하지 않는다.
  저장이 차단되면 초안 보존 불가를 알리고 로그인 이동 전에 사용자가 복사할 수 있게 한다.
- DB 이행은 컬럼 추가만 한다. 기존 DB 사본에서 내용·번호·쿠키 권한·좋아요·신고를 대조한다.
  회원 글 생성 후에는 회원 글을 이해하지 못하는 구버전으로 단순 롤백하지 않고 새 버전의 쓰기를 중지해 복구한다.
  데이터 삭제/역변환은 하지 않는다. 실제 배포와 운영 로그인 확인은 로컬 검증과 구분해 기록한다.
