# 미사용 및 장기 파일 관리 요구사항

> 작업 체크리스트. 현재 구현된 정책은 `backend/docs/storage.md`와 코드가 기준이다.

## 이번 작업의 범위

- [x] 저장소 `docs` 문서가 아니라 S3에 업로드하는 사진·포스터 등의 파일을 대상으로 삼는다.
- [x] 7일 미만을 포함해 현재 참조가 없는 파일을 관리자가 요청할 때 조회한다. 자동 보고는 실행하지 않는다.
- [x] 업로드가 완료되지 않은 `PENDING` 파일과 참조가 없는 `READY` 파일을 구분해 목록에 표시한다.
- [x] `PENDING`은 요청 시각, `READY`는 업로드 완료 또는 마지막 연결 해제 시각부터 미사용 기간을 센다.
- [x] 공연·공연 예매 포스터와 이미지, 활성 사진 보관함 항목, 일반·OTR 지원서 등에서 사용 중인 파일은 목록에서 제외한다. 참조 레지스트리뿐 아니라 실제 도메인 참조도 확인한다.
- [x] 관리자 API에 파일 ID·소유자 ID·상태·공개 범위·미사용 시각·7일 경과 여부를 페이지별로 표시한다. 원본 파일명과 저장소 키는 보내지 않는다.
- [x] 목록 조회는 DB와 S3 객체를 변경하지 않는다.
- [x] 기존 파일에 생성 시각이 없는 경우, 마이그레이션 직후 오래된 것으로 간주하지 않는 안전한 기준을 적용한다.
- [x] 관리자는 미사용 기간 7일 이상인 파일만 수동 삭제할 수 있다. 요청마다 참조와 기간을 다시 검사한다.
- [x] 삭제 결과를 감사 기록에 남기고, 실패한 삭제는 안전하게 재시도할 수 있다.
- [x] 관리자가 최대 100개 파일을 선택해 공통 확인 비밀번호를 한 번 입력하면 파일별 삭제 결과를 받는다.
- [x] 파일 삭제는 기존 지원서 삭제의 2차 확인 비밀번호를 재사용하며 별도 비밀번호 설정을 요구하지 않는다.
- [x] 자동 삭제와 S3 Lifecycle 설정은 이번 작업에 포함하지 않는다.

## 확인할 완료 조건

- [x] 7일 경계값, `PENDING`·`READY`, 참조 유무, 페이지 경계를 테스트로 검증한다.
- [x] 오래된 기존 행을 마이그레이션 직후 오래된 것으로 판정하지 않는지 검증한다.
- [x] 관리자 목록에 포함되는 정보가 정해진 항목으로 제한되는지 검증한다.
- [x] 실제 동작과 실행 방법을 `backend/docs/storage.md`에 반영한다.

- [x] 각 기능은 실패하는 테스트를 먼저 작성하고, 통과하는 최소 구현을 한 뒤 검증한다.
- [x] 기능 하나가 완성될 때마다 해당 변경만 커밋한다.
