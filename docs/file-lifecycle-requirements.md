# 미사용 및 장기 파일 관리 요구사항

> 작업 초안. 이 문서는 앞으로 만들 동작을 추적한다. 현재 구현된 정책은 `backend/docs/storage.md`와 코드가 기준이다.

## 이번 작업의 범위

- [ ] 생성 후 7일이 지난 파일 중 현재 참조가 없는 파일을 조회 대상으로 삼는다.
- [ ] 업로드가 완료되지 않은 `PENDING` 파일과 참조가 없는 `READY` 파일을 구분해 목록에 표시한다.
- [ ] 공연·공연 예매 포스터와 이미지, 사진 보관함, 일반·OTR 지원서 등에서 사용 중인 파일은 목록에서 제외한다. 참조 레지스트리뿐 아니라 실제 도메인 참조도 확인한다.
- [ ] 서버 로그에 후보 파일 ID, 상태, 생성 시각의 목록과 상태별·전체 건수를 보고한다. 원본 파일명과 저장소 키 등 불필요한 개인정보는 기록하지 않는다.
- [ ] 오래된 파일을 일정 개수씩 안정적으로 조회할 수 있다. 한 번에 전체 파일을 메모리에 올리지 않는다.
- [ ] 보고서는 매일 자동 실행되며, 각 실행의 기준 시각·대상 건수·실패 여부를 로그로 확인할 수 있다.
- [ ] 목록 조회는 DB와 S3 객체를 변경하지 않는다.
- [ ] 기존 파일에 생성 시각이 없는 경우, 마이그레이션 직후 오래된 것으로 간주하지 않는 안전한 기준을 적용한다.
- [ ] 자동 삭제와 S3 Lifecycle 설정은 이번 작업에 포함하지 않고 후속 이슈 #18에서 다룬다.

## 확인할 완료 조건

- [ ] 7일 경계값, `PENDING`·`READY`, 참조 유무, 페이지 경계를 테스트로 검증한다.
- [ ] 오래된 기존 행을 잘못 삭제 대상으로 판정하지 않는지 검증한다.
- [ ] 보고서에 포함되는 정보가 정해진 항목으로 제한되는지 검증한다.
- [ ] 실제 동작과 실행 방법을 `backend/docs/storage.md`에 반영한다.

## 진행 방식

- [x] 보고서 실행 방식은 매일 자동 실행으로 확정한다.
- [ ] 각 기능은 실패하는 테스트를 먼저 작성하고, 통과하는 최소 구현을 한 뒤 검증한다.
- [ ] 기능 하나가 완성될 때마다 해당 변경만 커밋한다.
- [ ] 작업 이슈를 프로젝트 #131에 넣고 `In Progress`로 표시한다.
- [ ] 최신 `dev`를 기준으로 검증한 뒤 PR을 만들고 `dev`에 병합한다.

## 이번에 하지 않는 것

- S3 객체 또는 `file_assets` 행 삭제, 자동 삭제 배치, 장기 보관된 참조 파일의 파기.
- 개인정보 보관기간 정책의 확정. 이는 별도 정책 결정이 필요하다.
