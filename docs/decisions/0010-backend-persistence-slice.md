# 0010. Backend 첫 영속화 구조

## 계기

첫 MySQL 세로 슬라이스를 구현하려면 인증 주체, Draft 공개 범위, 제출 스냅샷과 시간 저장 기준을 먼저 확정해야 했다.

## 결정

로그인 자격은 공통 `Account`가 소유하고 지원자와 공연사 멤버십은 별도 도메인으로 분리한다. 한 계정은 지원자이면서 여러 공연사의 멤버가 될 수 있다. MVP 공연사 역할은 `ADMIN`만 사용한다.

익명 Draft는 Application과 분리된 도메인·DB 기반만 구현하고, 식별·접근 보호와 개인정보 고지 계약이 정해지기 전에는 공개 API를 만들지 않는다. 제출 데이터는 배역·답변을 정규화하면서 전체 지원·공고·배역·동의 증거를 JSON 불변 스냅샷으로 함께 보존한다. 시각은 UTC `DATETIME(6)`로 저장하고 외부에는 offset이 있는 ISO-8601로 반환한다.

## 이유

인증 중복을 줄이면서 역할별 데이터와 공연사 소유권을 분리할 수 있다. 하이브리드 스냅샷은 조회 제약과 제출 당시 증거 재현을 함께 만족한다. 익명 공개 계약은 보안·개인정보 결정 없이 임의 확정하지 않는다.

## 영향

상세 구조와 보류 범위는 [설계 노트](../../design/backend-persistence-slice.md)를 따른다. Draft·제출 공개 API와 시드의 불완전 지원서 이관은 후속 결정을 거친다.
