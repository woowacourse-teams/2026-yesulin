# 공고 게시 상태와 섹션 검증

## 계기

공고의 작성 섹션이 독립 Aggregate라 게시 시점에 완성 여부를 조합해야 하며, 모집 기간에서 파생되는
화면 상태를 모두 DB 상태로 저장하면 시간 경과에 따라 상태가 어긋날 수 있다.

## 결정

application이 공고 행을 잠근 뒤 배역·일정·지원 폼 존재 여부와 모집 종료 시각을 검사하고 `Audition`을
`PUBLISHED`로 전이한다. 모집 시작 뒤 게시도 허용하되 종료 시각 이후 게시를 거부한다. 게시 API는
`PUT /api/v1/auditions/{auditionId}/publication`이며 최초 게시 시각을 유지하는 멱등 요청이다.

예정·모집 중·접수 마감은 별도 영속 상태로 두지 않고 `PUBLISHED`와 모집 기간으로 조회 시 계산한다.

## 이유

게시 트랜잭션이 독립 섹션을 명시적으로 조합하면서도 시간 경과만으로 바뀌는 값을 중복 저장하지 않는다.
공고 행 잠금은 게시와 섹션 전체 교체가 서로 다른 완성 상태를 보지 않게 한다.

## 영향

기본 정보·배역·일정·지원 폼 저장과 게시는 같은 공고 잠금을 사용한다. 배우용 공개 조회는 후속 읽기
모델에서 표시 상태를 계산한다.
