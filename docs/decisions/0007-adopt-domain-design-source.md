# 0007. 도메인 설계 정본 반영

## 계기

지원자 flowchart, API 목표 계약과 공개 정책의 인증 시점이 서로 달랐지만 최신 Notion 도메인 설계는 지원서 작성 뒤 최종 제출 전에 인증을 요구한다.

## 결정

Notion `도메인 설계`에서 확정된 회원 구분, 지원 흐름과 지원서 필드를 [도메인 설계 기준](../domain-design.md)에 정리해 현재 도메인 정본으로 사용한다. 구현과 다른 내용은 목표 설계로 덮어 쓰지 않고 구현 차이와 추가 설계 질문으로 분리한다.

## 이유

결정된 정책과 현재 프로토타입을 구분해야 Backend가 제출 전 인증 원칙을 지키고, 미결 사항도 임의의 모델로 확정하지 않는다.

## 영향

지원자 flowchart와 공개 정책은 인증 후 제출 흐름을 따른다. 제출·파일·지원서 조회 API는 인증과 소유권 계약이 결정될 때까지 Backend 목표에서 보류한다. 애플리케이션 코드는 별도 구현 작업에서 변경한다.
