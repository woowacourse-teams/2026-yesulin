# 지원 시작 선택과 제작사 작성 로컬 Draft

## 계기

비로그인 배우가 프로필 불러오기 선택을 놓친 채 지원서를 시작할 수 있었고, 기획사/제작사의 긴 공연·공고 작성 폼은 모달을 닫으면 모두 유실됐다.

## 결정

비로그인 배우가 `지원서 작성` 또는 `지원서 이어쓰기`를 누르면 로그인 후 프로필을 불러올지, 로그인 없이 이 기기에서 작성할지 한 번 선택한다. 로그인 성공 후에는 선택 배역과 로컬 Draft를 유지해 작성 화면으로 바로 복귀한다.

공연 추가와 공고 추가는 마지막 변경 600ms 뒤 trailing debounce로 현재 브라우저 IndexedDB에 자동 저장한다. 공연 Draft는 신규 공연 하나, 공고 Draft는 공연별 신규 공고 하나를 유지한다. 의도적으로 모달을 닫을 때는 대기 중 변경을 즉시 저장하고, 다시 열면 자동 복원하며, 생성 성공 때 삭제한다. 자동저장 상태와 실패를 폼 안에 표시한다.

## 이유

입력마다 요청하지 않으면서 새로고침·실수로 닫기에서 작성 내용을 복구하고, 로그인 선택권과 최종 제출 인증을 함께 유지한다.

## 영향

현재 저장은 프론트 검증용 로컬 Draft이며 서버 공고 `DRAFT`나 게시를 만들지 않는다. 계정 간 격리, 서버 동기화·충돌·보관 정책은 실제 API 연동 전에 별도 확정한다.
