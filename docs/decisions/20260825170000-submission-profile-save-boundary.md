# 제출과 프로필 저장의 책임 경계

## 계기

`이번 지원서 정보의 프로필 저장` 선택을 실제 Backend 공고에 연동하면서 프로필 갱신을 지원서 제출 API가
수행할지, 별도 요청으로 수행할지 정해야 했다.

## 결정

지원서 제출 API는 프로필을 변경하지 않는다. 저장을 선택하면 Frontend가 제출 성공 후 현재 프로필을
조회해 이번 지원서의 기본·추가 정보와 병합하고 프로필 PATCH를 호출한다. 값을 입력한 수집 필드만
덮어쓰며, 비워 둔 항목과 공고가 수집하지 않은 필드는 기존 프로필 값을 유지한다. 프로필 저장 실패는
제출 성공에 영향을 주지 않고 완료 화면에서 안내만 한다.

## 이유

확정된 제출 계약과 불변 스냅샷 확정이라는 단일 책임을 유지한다. 프로필 저장은 편의 기능이므로 그
실패가 유효한 제출을 롤백하면 안 된다. 프로필 PATCH의 섹션 교체 계약을 재사용해 Backend 추가 구현
없이 같은 검증 경로를 쓴다.

## 영향

제출 흐름, 프로필 PATCH 사용과 지원서·프로필 문서를 함께 맞췄다. 프로필 계속 보관에 대한 별도 선택
동의 UI는 아직 없으며 실서비스 공개 전에 결정한다.
