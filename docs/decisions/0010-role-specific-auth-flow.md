# 0010. 인증 주체별 로그인·가입 흐름

## 계기

지원자와 공연사가 같은 이메일 가입·로그인 UI를 사용하고, 공연사 가입은 확정되지 않은 외부 검증 입력을 요구해 최신 인증 정책과 달랐다.

## 결정

`/login`은 주체 선택을 유지한다. 지원자는 카카오·네이버·Google 소셜 로그인만 사용하며 첫 로그인 시 계정을 자동 생성한다. 별도 지원자 회원가입 화면과 API는 두지 않는다. 공연사는 이메일·비밀번호로 로그인하고 `/signup`에서 공연사명, 휴대폰 번호, 이메일, 비밀번호를 입력한다. 비밀번호 확인과 필수 약관 동의는 유지한다.

공연사 상태는 `PENDING`, `ACTIVE`다. 가입 직후에는 `PENDING`이며 공연사 정보 설정만 가능하다. 공연 조회·공고·심사 기능은 운영진 수동 확인으로 `ACTIVE`가 된 뒤 허용한다. 대기 화면은 등록한 휴대폰·이메일로 안내가 발송됨을 알리고 카카오톡 채널 문의를 제공한다.

## 이유

지원자는 소셜 인증으로 진입 단계를 줄이고, 공연사는 운영진 확인 전 지원자 정보와 관리 기능에 접근하지 못하게 한다.

## 영향

인증 UI, 지원서 인증 복귀, 공연사 접근 제한, MSW, 도메인·API·flowchart 문서를 함께 맞춘다. 실제 OAuth, 문자·이메일 발송, 인증 자격 전달 방식과 상태 변경 API는 Backend 계약에서 별도로 결정한다.
