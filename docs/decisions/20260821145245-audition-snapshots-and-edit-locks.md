# 공고 스냅샷과 수정 잠금

## 계기

공연 배역을 등록 뒤 변경하면 공고의 모집 기준이 흔들릴 수 있고, 공연 배역 이름을 실시간 참조하면 공고와
지원서 표시도 함께 바뀔 수 있다. 기존 공고 수정 범위도 모집 진행 상태와 맞지 않았다.

## 결정

공연 배역은 공연 등록 시 확정하며 이후 추가·수정·삭제하지 않는다. 공고 게시 시 선택한 공연 배역 이름을
공고 배역에 복사하고, 게시된 공고와 제출 지원서는 이 스냅샷을 사용한다.

저장 상태 `DRAFT`, `PUBLISHED`, `CLOSED`와 화면 상태를 분리한다. `UPCOMING`, `OPEN`,
`RECRUIT_CLOSED`는 Backend가 모집 기간으로 계산한다. `UPCOMING`에서는 모든 항목을 수정한다.
`OPEN`에서는 공고명과 모집 종료 시각의 연장만 허용하며 모집 시작 변경과 종료 단축을 막는다.
`RECRUIT_CLOSED`에서는 모든 수정을 막는다. 추가 질문은 텍스트형
최대 10개이며 모집 시작 뒤 수정할 수 없다.

## 이유

지원자가 확인한 모집 조건과 배역명을 보존하고 시간 경과에 따른 수정 권한을 서버에서 일관되게 강제한다.

## 영향

공고 배역 저장·게시 트랜잭션, 상태별 command 검증, 공개 공고와 지원서 읽기 모델을 함께 변경한다.
공고 상태별 command 검증과 공개 공고 변경 반영을 함께 맞춘다.
