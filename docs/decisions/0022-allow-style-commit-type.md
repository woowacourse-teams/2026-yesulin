# 0022. style 커밋 타입 허용

## 계기

UI 색상, 간격, 아이콘과 파비콘 같은 시각 자산만 바꾸는 커밋을 기능 추가인 `feat`나 저장소 유지보수인 `chore`로 분류해야 해 변경 의도가 흐려졌다.

## 결정

커밋과 브랜치 타입에 `style`을 추가한다. `style`은 동작과 데이터 계약을 바꾸지 않는 UI 시각 표현, 정적 시각 자산과 코드 포맷 변경에 사용한다. 의존성, 빌드 도구와 일반 유지보수는 계속 `chore`를 사용한다.

## 이유

사용자에게 보이는 시각 변경과 개발 환경 유지보수를 분리하면 커밋 이력을 목적별로 읽기 쉽다.

## 영향

commitlint의 `type-enum`과 Git 컨벤션이 `style`을 허용한다. 시각 변경에 기능이나 계약 변경이 함께 포함되면 변경의 주된 목적에 맞는 다른 타입을 사용한다.
