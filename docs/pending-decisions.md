# 미결정 사항

현재 코드를 기준으로 결론을 낼 수 없고 MVP 정본에서 제외한 항목이다. 답을 추측하지 말고 관련 기능을 구현할 때 사용자 결정을 받는다.

| 주제 | 결정할 내용 |
| --- | --- |
| 프로필 저장 동의 | 현재 `프로필에도 저장` 선택과 별도의 지속 보관 동의를 어떻게 구분하고 기록할지 |
| 서버 Draft | 도입 여부, 식별자, 충돌 해결, 만료와 삭제 기준 |
| 소셜 계정 연결 | 복수 provider 연결·해제, 동일 이메일 처리, 재인증 절차 |
| 사진 정제 | Lambda와 EC2 Worker 중 실행 위치, 픽셀·동시 처리 제한, 실패 복구 |
| 파일 보관·파기 | 참조 중인 사진·포스터와 삭제 상태로 남긴 파일 메타데이터의 보관기간, 삭제 시 CDN 캐시 무효화가 필요한 상황 |
| 제출 정정 | 제출 스냅샷 정정 시 원본 변경과 새 버전 중 어떤 모델을 사용할지 |
| 공고 장소 변경 | 지원자가 이미 제출한 뒤 연습·오디션 장소를 변경할 수 있는지, 변경한다면 지원서별 장소 스냅샷과 변경 안내를 어떻게 남길지 |
| 목록 페이지 | 지원서·심사 목록 pagination 방식과 기본 크기 |
| 무료 공연 예매 마감 | 현재는 회차 시작 시각까지 예매할 수 있다. 취소 마감처럼 시작 1시간 전 등으로 앞당길지 |
| 무료 공연 예매자 정보 보유기간 | 이름·휴대폰을 언제 파기할지와 파기 방식. 예매 화면은 "공연 종료 후 지체 없이 파기"를 임시로 안내하며 실제 파기는 없다 |
| 무료 공연 예매 오픈 예약 | 공개와 동시에 예매가 열리는 현재 방식 외에 예매 시작 시각을 예약할지 |
| 추가 합격자 안내 문구 | 확정 뒤 등록한 추가 합격자에게 1차와 같은 "합격입니다" 문구를 보낼지, "추가 합격입니다"처럼 구분할지 |
| 오디션 일정표 개인정보 보유기간 | 배우·담당자 이름·휴대폰과 문자 본문(개인 링크 포함)을 언제, 어떤 기준(오디션 종료 후 등)으로 파기할지 |
| 게시 공고 제작사 허락 기록 | 게시 뒤 받은 제작사 허락을 시스템에 남길지(요청 전·허락·거절 상태, 연락 일시·메모). 현재는 거절 시 숨기기만 있고 감사 기록에 가져온 운영자·시각만 남는다 |
| 게시 공고 원문 동기화 | 원문이 수정·삭제됐을 때 자동으로 다시 가져오거나 숨길지. 현재는 운영자가 수동으로 다시 가져오거나 숨긴다 |

개인정보 처리방침의 수탁자·국외 이전·보유기간·권리 행사는 정식 출시 준비 범위에서 별도로 확정한다.
