# 미결정 사항

현재 코드를 기준으로 결론을 낼 수 없고 MVP 정본에서 제외한 항목이다. 답을 추측하지 말고 관련 기능을 구현할 때 사용자 결정을 받는다.

| 주제 | 결정할 내용 |
| --- | --- |
| PostHog 처리 근거 검토 | 2026-10-29 운영자는 미국 리전에서 기본 수집·사용자 거부 방식을 유지하기로 결정했다. 수집·국외 이전의 법적 근거가 확인됐다는 뜻은 아니며 별도 검토 결과는 아직 없다. 실제 수집 범위는 `docs/policies/public/analytics-notice.md`, 설정·검증 상태는 `frontend/docs/posthog-setup.md`를 따른다 |
| 커뮤니티 신고 알림 | 전용 Slack 채널을 우선 사용한다. 실제 웹훅·환경별 링크 설정과 수신 확인이 남았다. 현재 구현은 대상별 첫 신고만 알리고 추가 신고는 저장한다. 매 신고 알림이 필요해지면 정책을 변경한다 |
| 의견 보내기 연락처·내용·사진 보유기간 | 의견에 남긴 연락처·내용·브라우저 정보와 첨부 사진을 언제 파기할지, 답장 기록을 둘지. 현재는 DB·비공개 저장소에 저장만 하고 자동 파기는 없다(운영자 조회 화면은 `/admin/feedback`에 있다). 쌓이는 양을 보고 정하며, 정하면 개인정보처리방침에도 반영한다. 제안: 처리 완료 후 1년 |
| 커뮤니티 데이터 처리 | 익명 관리 수단의 유지 기간, 글·댓글·신고 기록의 보관·삭제·파기 기준. 분석 식별과 작성물 소유 확인을 별도 목적으로 구분한다 |
| 커뮤니티 후속 검증 | 팀원·테스트 활동 제외와 익명 고유 사용자 측정 방법, 자유게시판에 맞춘 새 실험 기준. 구상만 유지하고 구현은 후순위이며 첫 출시를 막지 않는다 |
| 프로필 저장 동의 | 현재 `프로필에도 저장` 선택과 별도의 지속 보관 동의를 어떻게 구분하고 기록할지 |
| 서버 Draft | 도입 여부, 식별자, 충돌 해결, 만료와 삭제 기준 |
| 일반 회원 정의와 약관 | 소셜 로그인 회원을 배우·팬이 함께 쓰는 일반 회원으로 보도록 바꿨다(프로필을 등록한 회원이 배우). 이용약관과 개인정보 처리방침은 아직 이 계정을 "배우 계정"으로 정의하고 만 14세 확인을 배우 계정 생성 조건으로 적는다. 일반 회원으로 어떻게 정의·고지할지, 연령 확인 문구를 어떻게 정할지는 정식 출시 정책 작업에서 정한다 |
| 배우 페이지 응원 글 운영 | 응원 글 신고와 운영자 삭제, 같은 회원의 도배 제한, 배우 본인이 자기 페이지의 응원 글을 숨기거나 지울 수 있게 할지, 탈퇴한 회원의 응원 글 처리. 작성자는 익명이지만 실제 인물의 공개 페이지에 남는 글이라 공개 확대 전에 정한다 |
| 소셜 계정 연결 | 복수 provider 연결·해제, 동일 이메일 처리, 재인증 절차 |
| 사진 정제 | Lambda와 EC2 Worker 중 실행 위치, 픽셀·동시 처리 제한, 실패 복구 |
| 파일 보관·파기 | 참조 중인 사진·포스터와 삭제 상태로 남긴 파일 메타데이터의 보관기간, 삭제 시 CDN 캐시 무효화가 필요한 상황 |
| 제출 정정 | 제출 스냅샷 정정 시 원본 변경과 새 버전 중 어떤 모델을 사용할지 |
| 공고 장소 변경 | 지원자가 이미 제출한 뒤 연습·오디션 장소를 변경할 수 있는지, 변경한다면 지원서별 장소 스냅샷과 변경 안내를 어떻게 남길지 |
| 목록 페이지 | 지원서·심사 목록 pagination 방식과 기본 크기 |
| 무료 공연 예매 마감 | 현재는 회차 시작 시각까지 예매할 수 있다. 취소 마감처럼 시작 1시간 전 등으로 앞당길지 |
| 무료 공연 예매자 정보 보유기간 | 이름·휴대폰을 언제 파기할지와 파기 방식. 예매 화면은 "공연 종료 후 지체 없이 파기"를 임시로 안내하며 실제 파기는 없다 |
| 무료 공연 예매 오픈 예약 | 공개와 동시에 예매가 열리는 현재 방식 외에 예매 시작 시각을 예약할지 |
| 추가 합격자 안내 문구 | 확정 뒤 등록한 추가 합격자에게 1차와 같은 "합격입니다" 문구를 보낼지, "추가 합격입니다"처럼 구분할지 |
| 오디션 일정표 개인정보 보유기간 | 배우·담당자 이름·휴대폰과 문자 본문(개인 링크 포함)을 언제, 어떤 기준(오디션 종료 후 등)으로 파기할지 |
| 게시 공고 제작사 허락 기록 | 게시 뒤 받은 제작사 허락을 시스템에 남길지(요청 전·허락·거절 상태, 연락 일시·메모). 현재는 거절 시 숨기기만 있고 감사 기록에 가져온 운영자·시각만 남는다 |
| 게시 공고 원문 동기화 | 원문이 수정·삭제됐을 때 자동으로 다시 가져오거나 숨길지. 현재는 운영자가 수동으로 다시 가져오거나 숨긴다 |
| 공연사 정보 개인정보 처리 | 공개된 자료에서 모은 대표자 이름·주소를 처리방침에 어떻게 밝힐지(수집 출처·목적·처리 정지 요구 안내), 공개 동의를 어떤 방식으로 받고 기록할지(현재는 운영자가 동의 여부만 체크), 수정·삭제 요청을 카카오톡 채널 대신 별도 요청 폼으로 받을지와 요청자 정보 보유기간 |
| 공연사 정보 출처 표기 | KOPIS 등 외부 자료로 채운 정보의 출처를 공개 화면에 표기할지와 표기 방식. KOPIS 연동 전에 이용 조건과 함께 정한다 |
| 공연사 서비스 요금 | `/producer-service`는 "베타 기간 · 지금은 0원 · 요금제가 생기면 미리 안내"로 표시한다. 유료 전환 시점·대상 기능·기존 공연사 사전 안내 기간은 정하지 않았다 |

개인정보 처리방침의 수탁자·국외 이전·보유기간·권리 행사는 정식 출시 준비 범위에서 별도로 확정한다.


커뮤니티 로그인 참여의 P01~P04는 2026-11-04 사용자 결정으로 확정했다.
