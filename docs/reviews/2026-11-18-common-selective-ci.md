## GitHub PR 실측

검증 PR 두 개를 `test/ci-routing-base`에 열었다. 프론트 사례는 `frontend/package.json`, 백엔드 사례는 `backend/src/test/resources/application.properties`에 각각 공백 한 줄만 추가했다. 구현 PR에는 사례 파일과 검증 전용 워크플로가 포함되지 않는다.

비교의 분리 전 실행은 기존 `dev`의 CI를 검증 브랜치 전용 워크플로로 복제한 것이다. PR 실행 조건과 체크 표시 이름만 검증용으로 바꾸고 기존 빌드·테스트 단계는 유지했다. 같은 PR을 대상으로 경로별 CI도 함께 돌렸으며, 네 잡의 체크아웃 로그를 대조해 비교 쌍마다 동일한 임시 머지 SHA였음을 확인했다.

| 변경 | 분리 후 실행 | 필수 체크 완료까지 | 두 잡 실행 시간 합계 |
| --- | --- | ---: | ---: |
| [프론트 전용 #608](https://github.com/woowacourse-teams/2026-yesulin/pull/608) | 프론트 설치·린트·빌드 성공, 백엔드 빌드·테스트 생략 | 124 → 121초 (3초 감소) | 153 → 126초 (27초 감소) |

완료 시간은 실행 생성부터 두 체크가 끝날 때까지다. CI 두 작업이 병렬이므로 완료 시간과 작업 시간 합계의 변화는 다를 수 있다. 각 사례 첫 시도 1쌍이며, 실행된 작업은 모두 캐시를 복원했다. 프론트 사례의 백엔드 러너 이미지 버전은 분리 전후에 달랐다. 이 값을 반복 측정의 평균 절감량으로 해석하지 않는다.

[실행별 CSV](./2026-11-18-common-selective-ci-pr-runs.csv)에 실행·잡 링크, 변경 경로, 비교 기준 SHA, 실제 checkout SHA, 실행 시각, 생략된 단계와 캐시 관측 결과를 기록했다. 별도 `workflow_dispatch` 및 보호 브랜치의 push 동작은 이번 PR 실측 범위 밖이다.

원격 검증 독립 평가 1회에서 PR 변경 범위, 각 작업의 실행·생략, 실제 checkout SHA와 검증 브랜치 격리를 재확인했다. 원격 검증에서 신규 확정 문제 발견·해결·미해결은 각각 0건이다.
