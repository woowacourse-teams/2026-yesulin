## 검증 근거

- 로컬 브라우저에서 공용 폼과 저장 본문 컴포넌트를 연결했다. 1422px에서 두 패널의 본문 시작선이 일치하고, 기존 빈 문단과 Enter 두 번으로 새로 만든 빈 문단의 높이가 작성·미리보기·저장 본문에서 각각 약 29px였다. 433px에서 키보드로 모드를 바꾼 뒤 입력 내용이 남았으며 페이지 가로 넘침이 없었다. 확인용 라우트는 제거했다.
- Jsoup 1.23.2로 빈 문단 0~2개가 있는 예시를 정리해 입력 HTML이 보존됨을 확인했다. 기존 문제 [2026-11-16-auditionpost-body-line-breaks-F01](2026-11-16-auditionpost-body-line-breaks.md)의 표시 결함을 해결했다.
- 프론트 `npm test` 213파일 1,165건 통과, `npm run lint` 및 `npm run build` 종료 코드 0. 백엔드 `./gradlew --offline checkstyleMain checkstyleTest test --tests 'art.yesulin.auditionpost.application.AuditionPostBodySanitizerTest'` 테스트 6건 통과와 Checkstyle 성공.
- 관리자 작성·수정과 기획사 작성·수정은 `AuditionPostForm`을 사용한다. 관리자 저장 미리보기와 공개 상세는 `AuditionPostContent`로 같은 본문 스타일을 적용한다. 기존 조회 지점, 첨부 추적, 게시 성공 이벤트와 대시보드 조건을 확인했다. 작성 중 미리보기는 별도 분석 이벤트를 만들지 않는다.
