## 관리자 흐름

`/admin/openchat`에서 관리자 확인이 끝나면 `마감 안내 만들기`를 제공한다. 한국 시간 기준 `내일 마감`을 기본으로 열고 `오늘 마감`도 선택할 수 있다. 공개 목록 API의 모집 중·마감일 순 정렬을 재사용한다. 목표 마감일을 모두 지나거나 날짜 없는 공고가 시작되는 페이지까지 읽고, 정확히 일치하는 날짜만 노출한다. 중복 번호는 한 번만 표시하며 페이지 요청 중 실패하면 빈 목록과 구분해 재시도할 수 있게 한다.

운영자가 보낼 공고를 선택하면 인사말, 절대 날짜, 공고 제목과 예술in 상세 링크를 포함한 문구를 만든다. 운영자가 상세를 확인하고 선택을 조정한 뒤 문구를 복사한다. 편집한 문구가 있으면 선택 변경 시 재생성 전에 확인한다. 열린 화면이 한국 시간 자정을 넘기면 기준 날짜를 갱신하고 복사 전에 미리보기를 다시 확인할 수 있게 한다.

## 링크와 유입 집계

- 링크는 `/posts/{postId}?src=kakao_openchat&utm_campaign=deadline_reminder_20261127_d1` 형식을 쓴다. 키에 마감일과 안내 시점(`d1`·`d0`)을 넣는다. 같은 마감일·시점의 모든 공고 링크에 같은 값을 쓰므로 그 조합으로 여러 번 올리면 합산된다. 공고별 수치는 `post_id`로 본다.
- 공개 상세 라우트에서 카카오 출처와 캠페인의 형식·날짜를 검증하고 그 공고 상세에 명시적으로 전달한다. URL 정리와 컴포넌트 실행 순서에 의존하지 않는다. 공개 상세 로드 성공 시 기존 `openchat_landed`에 검증된 캠페인 식별값만 더한다. 다른 공고를 둘러보거나 태그 없는 링크로 재접근하거나 원문으로 이동할 때 리마인드에 귀속하지 않는다. 기존 공고별 누적 API 및 일반 유입의 분모를 유지한다.
- PostHog의 공고 대시보드에서 캠페인 전체와 공고별 `person_id` 고유 수를 조회한다. 캠페인 전체에서 여러 공고를 본 식별자는 한 번 센다. 운영 이벤트 중 내부·테스트를 제외하고 분석 거부를 존중한다. 전달받은 링크로 공개 상세에 도달한 경우도 관측된다. 메시지 열람 수는 알 수 없다.
- 현재 PostHog SDK는 캠페인 자동 저장이 꺼져 있고 이벤트 허용 목록에 리마인드 속성이 없다. 해당 속성 수집이 적용된 이후부터 캠페인별 보고서를 채운다. GA/GTM의 실제 캠페인 수신은 확인하지 않았다.
