# 공용 AI 작업

1. 추출 결과를 저장한 트랜잭션에서 jobId당 PdfAiJob을 한 번 만든다. 심사는 배역 스냅샷,
   배우 가져오기는 reviewId=null·roles=[]다. 추출 실패·비활성·본문 없음/초과·레거시 완료는 SKIPPED다.
2. 새 PENDING 작업 생성 시 이벤트를 발행하고, 콜백 트랜잭션 커밋 뒤 Dispatcher가 비동기 Worker를 깨운다.
   롤백·중복 enqueue·SKIPPED는 새 실행 신호를 만들지 않는다. Dispatcher는 신호를 합치고 노드 실행 수를 제한한다.
   QueueService.claim이 DB Gate를 잠가 전역 상한·호출 간격·lease를 획득한다.
   획득 커밋 뒤 다음 호출 간격에 맞춰 신호 하나를 예약해 다른 실행 슬롯도 채운다. 예약 신호는 합치고
   빈 큐에서는 새 예약을 만들지 않는다. 처리 가능한 다음 작업은 주기 실행을 기다리지 않고 이어서 처리한다.
   호출 간격/전역 상한에 막히면 실행 스레드는 종료하며 예약 신호나 주기 신호가 다시 깨운다.
   Scheduler는 5초 기본 주기로 같은 Dispatcher를 깨워 재시도·중단·유실된 신호를 복구한다.
3. DB 트랜잭션 밖에서 모델을 호출하고 응답 형식·원문 근거를 검사한다.
   dev에서는 Luna의 형식/근거 검증 실패에 한해 Sol 작업을 큐에 다시 넣는다. 정상 null·응답 잘림·429는
   승격 사유가 아니다. Sol 호출도 전역 gate를 획득하고 재시도 중에는 Sol을 유지한다.
   모델별 서킷이 열려 있으면 작업을 획득하지 않는다. 기본/승격 대기열의 선두를 각각 확인하여
   Luna 차단 때문에 처리 가능한 Sol 작업까지 막히지 않게 한다.
4. 성공은 AI resultJson 저장과 동기 이벤트 반영을 같은 트랜잭션으로 커밋한다.
   심사는 이름·배역·READY 반영(수동 배역·메모·판정 보호), 배우는 최종 완료 시각과 제안 유무에 따른 일일 집계를 반영한다.
5. 일시 실패는 PENDING+백오프, 영구 실패/시도 소진은 FAILED다. 심사는 NEEDS_REVIEW,
   배우는 원본 추출 상태를 최종 확정하고 유효 제안이 없으면 일일 성공 집계에 포함하지 않는다.
6. 만료 lease를 복구하고 오래된 응답은 무시한다. 배우 닫기·TTL 삭제에서는 AI 결과도 지워 개인정보를 남기지 않는다.

일반 추출 payload는 AI 결과로 덮어쓰지 않는다. 실패해도 심사의 원문·사진과 담당자 입력은 유지한다.
