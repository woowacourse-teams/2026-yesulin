# Audit 작업 규칙

최상위와 backend/frontend 작업 규칙을 먼저 적용한다. 이 문서는 심사 도메인의 세부 기준만 추가한다.

1. 도메인 CLAUDE.md·README.md는 `docs/`에 둔다. `docs/CLAUDE.md`는 같은 폴더의 `@AGENTS.md`를 참조한다.
   `docs/README.md`에서 대상 기능의 흐름과 기술 정책을 읽는다. flow는 진입·단계·완료·실패를,
   policy는 불변식·상한·재시도·호환성·미결정을 다룬다. 세부 패키지에 README를 추가하지 않는다.
2. 평가표는 `docs/reviews/criteria.md` 버전과 이번 변경 시나리오로 만든다. 기본 독립 평가 1회이며
   현재 도메인에 추가 전체 평가 의무는 없다. 발견 문제 수정 후에는 관련 검증만 반복한다.
3. Lambda/AI 실제 배포·모델 호출을 코드/로컬 검증과 구분한다. 300건·장애 복구·모델 정확도는
   측정 없이 완료나 수치로 주장하지 않는다. 개인정보 PDF/키를 평가 자료나 PR에 넣지 않는다.
4. 추출 payload 불변, 동일 콜백 멱등, 수동 판정·메모·배역 보호, 실패 때 진행률 종료 여부를 평가한다.
   SHA가 콜백 중복인지 원본 중복인지 구분한다. 원본 재등록 방지는 아직 미구현이다.
5. 기존 API·마이그레이션·독립 추출 확인 화면과 현재 소비자를 조사한 뒤 미사용 여부를 판단한다.
   승인 흐름 밖 SERVER 실험·옛 AI probe는 자기 참조나 테스트만을 근거로 유지하지 않는다.
   제거하지 않은 호환 경로는 소비자와 제거 조건을 평가 기록에 남긴다.
6. 결과는 `docs/reviews/<작업 ID>.md`, PR에는 공통 양식의 건수·문제 ID와 링크를 남긴다.
   평가 기록에는 해당 시점과 범위를 적고 예전 테스트 결과를 새 실행인 것처럼 기재하지 않는다.
