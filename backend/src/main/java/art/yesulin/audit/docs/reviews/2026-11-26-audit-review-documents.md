- R1–R3 PASS. Spring 도메인·HTTP 테스트 및 로컬 H2·S3에서 로그인, 서명 PUT, 형식 제한, 원본의 첨부 다운로드·SHA를 검증했다. 신규 작업에는 PDF 추출기와 구분되는 원본 경로가 있다. 배우 업로드는 PDF만 받는다.
- R4–R5 PASS. 국립극단의 2022년 공개 DOCX 양식을 로컬 Spring으로 접수하고 원본을 S3에 직접 업로드했다. 실제 변환 이미지에 이벤트를 2회 전달하고 원본 바이트, 미리보기와 기존 PDFium 추출 결과의 SHA, 한 개의 지원자 항목을 확인했다. 손상 문서 및 콜백 거부·재시도 시나리오에서 수동 메모와 판정을 확인했다. 로컬 SQS 봉투 전달과 기존 추출기 호출은 각각 테스트 코드에서 구동했다.
- R6 PASS. 가상 응답을 사용한 Chrome·모바일 화면과 프론트 회귀 테스트로 파일 형식, PDF 우선순위, 처리 중·실패·완료 원본 다운로드를 확인했다.
- R7 PASS. 별도 LocalStack S3+SQS에서 실제 객체 세 건을 생성해 originals/만 변환 큐에, inputs/만 기존 알림에 들어가고 previews/는 재호출되지 않음을 확인했다. CloudFormation cfn-lint 통과. 운영 AWS의 실제 권한·트리거는 별도 적용 대상이다.
- R8 FAIL (원본 배치 재현). 공개한 [공연사 빈 양식](https://www.ntck.or.kr/ko/content/board/notice/50275/form)을 macOS 한컴에서 직접 인쇄한 기준본은 4쪽이다. 두 엔진 모두 5쪽을 생성했고 사진란과 기본정보 표가 첫 쪽에서 둘째 쪽으로 이동했다. 동일 빈 양식을 ahwp로 편집해 가상의 이름·경력·배역과 합성 초상을 원래 표 칸에 넣었다. 같은 파일의 한컴 출력과 워커는 각각 4쪽이고 rhwp는 5쪽이다. 1쪽에 이름·사진·경력 행은 세 출력에 모두 표시됐다. 두 엔진 모두 한컴에서 보이는 1쪽 상단 작품명과 로고의 위치를 재현하지 못했고, 워커는 자기소개서 구역의 시작을 1쪽으로 당겼다. 한글 서식 전반의 재현성을 주장할 수 없다. 한글 확장자는 명시한 환경에서만 열고 미리보기에 안내와 원본 다운로드를 제공한다.
