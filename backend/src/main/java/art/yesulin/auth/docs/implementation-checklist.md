- 1~2는 TDD 요청 전에 작성한 코드이며 회귀 검증으로 기록한다. 3번부터 RED → GREEN → REFACTOR를 따른다.

## 구현 목록

- [ ] 1. 최초 메일 실패와 가입 성공을 분리하고 현재 세션에 최신 회원 상태를 반영한다.
- [ ] 2. 로그인 후 새 세션으로 화면에 진입하고 탭 복귀와 늦은 응답 경합에서 인증 상태를 복구한다.
- [ ] 3. 6자리 인증 코드, 5분 만료, 재전송 대기와 입력 실패 횟수를 도메인 규칙으로 구현한다.
- [ ] 4. 코드를 해시로 저장하고 메일 발송, 재전송, 검증을 기존 인증 테이블에서 처리한다.
- [ ] 5. 로그인한 공연사의 코드 검증 API와 세션 갱신, 기존 링크의 한시적 호환을 제공한다.
- [ ] 6. 인증 대기 화면에 6자리 입력과 오류/재전송/완료 상태를 제공하고 API 타입과 MSW를 맞춘다.
- [ ] 7. 최종 통합 검증, 확장 범위 독립 평가와 이슈/PR 기록을 마친다.

## 검증 기록

### 1~2 사전 작업

- 백엔드 인증 관련 테스트와 Checkstyle 통과, 전체 `./gradlew build` 통과.
- 프론트 전체 767개 통과, lint/build 통과. Node 26에서는 `NODE_OPTIONS=--no-experimental-webstorage`로 실행했다.
- 독립 평가가 발견한 과거 요청 실패 응답의 준비 상태 경합을 수정하고 관련 9개 테스트를 통과했다.
- 운영 메일 미수신 원인과 실제 수신함 전달 여부는 아직 미확인이다.

### 3 이후 TDD

각 기능의 RED, GREEN, REFACTOR 근거를 해당 커밋에서 추가한다.
