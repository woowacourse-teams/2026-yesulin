## 검증 기록

### 1~2 사전 작업

- 백엔드 인증 관련 테스트와 Checkstyle 통과, 전체 `./gradlew build` 통과.
- 프론트 전체 767개 통과, lint/build 통과. Node 26에서는 `NODE_OPTIONS=--no-experimental-webstorage`로 실행했다.
- 독립 평가가 발견한 과거 요청 실패 응답의 준비 상태 경합을 수정하고 관련 9개 테스트를 통과했다.
- 운영 메일 미수신 원인과 실제 수신함 전달 여부는 아직 미확인이다.

### 3 이후 TDD

각 기능의 RED, GREEN, REFACTOR 근거를 해당 커밋에서 추가한다.

### 3. 코드 도메인

- RED: `VerificationCodeTest`, `EmailVerificationCodeTest` 실행 시 미구현 타입과 메서드로 컴파일 실패를 확인했다.
- GREEN: 선행 0 보존, ASCII 숫자 6자리, 진단 출력 비노출, 5분 만료 경계, 5회 실패 제한, 60초 재전송 경계 6개 테스트 통과.
- REFACTOR: 만료·재전송·시도 횟수 판단을 `EmailVerification`에 모으고 코드를 `VerificationCode` 값 객체로 분리했다.
- 정책 기본값: 발급당 실패 5회, 재전송 간격 60초. 기존 만료 5분은 유지한다.

### 4. 코드 저장과 검증

- RED: 단위 테스트가 `verifyCode`, 코드 전용 오류, 코드 메일 생성 미구현으로 실패했다.
- GREEN: 메일의 6자리와 링크 미포함, 해시 저장, 본인 인증, 오입력, 5회 잠금, 만료, 타인 코드 거절을 단위 테스트로 확인했다.
- DB 통합: 잘못된 입력 후 트랜잭션이 끝나도 실패 횟수가 누적되고, 60초 재전송 제한과 이전 코드 무효화를 확인했다.
- REFACTOR: 코드 매칭, 실패 횟수, 만료, 기존 링크 처리를 작은 메서드로 분리했다.
- 검증 중 트랜잭션 밖 stream 조회와 H2 복수 컬럼 ALTER 문법 문제를 수정했다.

### 5. HTTP 계약과 호환

- RED: 프론트 API 단위 테스트가 `verifyProducerEmailCode` 미구현으로 실패했다.
- GREEN: 선행 0 문자열, PATCH/CSRF/세션 전달, 서버 오류 전파 테스트 통과.
- 실제 HTTP: 별도 H2와 로컬 SMTP로 가입 201/PENDING 로그인, 형식/오입력 거절, 정답 200/ACTIVE 세션/no-store,
  비로그인 401, 타인 코드 400, 5회 잠금과 재전송 제한 409를 확인했다. 외부 메일은 발송하지 않았다.
- REFACTOR: API 오류 처리와 요청 옵션을 작은 함수로 모으고 신규 메일에서 쓰지 않는 URL 설정을 제거했다.
- 이전 링크는 회원 ID만 projection으로 조회한 뒤 회원 잠금 후 소비해 중복 링크와 재전송의 순서를 맞춘다.

### 6. 인증 화면

- RED: 기존 인증 화면에 6자리 입력 필드가 없어 UI 테스트 2개가 실패했다.
- GREEN: 선행 0 입력, 형식 오류, 서버 오류 안내, 중복 제출 억제, 코드 검증 응답에 따른 상태 적용을 단위 테스트로 확인했다.
- REFACTOR: 화면 표시, 비동기 작업, 세션의 응답 경합 제어를 분리했다. 새 구현 로직은 삼항/else 없이 작은 함수로 작성했다.
- 실제 브라우저: 로그인 → 인증 대기 → 재전송 → 6자리 입력 → 공고 관리 진입 → 새로고침 후 유지까지 확인했다.
- 독립 평가 수정: 후속 GET 실패가 인증 성공을 뒤집지 않고, 늦은 완료가 로그아웃한 계정을 복원하지 않도록 표적 테스트를 추가했다.
