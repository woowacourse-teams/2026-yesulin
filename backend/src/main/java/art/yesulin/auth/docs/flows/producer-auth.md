# 공연사 가입과 인증 복구

회원가입은 `PENDING` 계정을 저장한 뒤 인증 메일을 요청하고, 프론트가 비밀번호 로그인으로 세션을 만든다.
메일은 5분 유효한 6자리 코드이며 재전송 시 기존 발급 정보를 교체한다. `ACTIVE` 전환은 이메일 인증 또는 운영자 수동
활성화로만 수행한다. 미인증 세션으로는 프로필과 메일 재전송만 허용한다.

코드는 가입/로그인한 `PENDING` 공연사 세션의 회원에게만 검증한다. 원문은 저장하지 않고 해시만 보관한다.
입력 실패는 발급당 5회까지 기록하며, 5회 실패 후에는 올바른 코드도 거절하고 재전송을 안내한다.
재전송 대기는 발급 후 60초다. 만료·실패 횟수·재전송 기준은 서버가 판단하고 실패 횟수는 DB에 남긴다.
기존 링크는 전환 전 발급된 토큰에 한해서 기존 5분 만료까지 호환한다. 코드 발급 정보는 링크로 인증할 수 없다.
다른 브라우저의 기존 세션도 현재 세션 조회 시 회원 상태를 다시 읽는다.

이미 저장된 계정은 초기 메일 발송 실패와 무관하게 가입 성공으로 응답한다. 운영자는 관리자 기획사·제작사 목록에서
인증 대기 계정의 기존 가입 주소로 재전송할 수 있다. 본인 재전송과 같은 60초 제한을 적용하고 계정 상태는 유지한다.
재전송 시 새 코드만 유효하며 해당 코드의 기본 유효 시간은 5분이다. 관리자 요청은 애플리케이션 로그의
`ADMIN_VERIFICATION_RESEND_REQUESTED` 이벤트로 실행자와 대상 회원 ID를 남긴다.

관리자 애플리케이션 로그에서는 최초 발송의 `INITIAL_VERIFICATION_FAILED`, 본인 재전송의
`VERIFICATION_RESEND_FAILED`, 관리자 재전송의 `ADMIN_VERIFICATION_RESEND_FAILED`를 검색한다.
이벤트 상세에는 `mailFailureReason`, 예외 종류, `requestId`와 확인 가능한 `smtpStatus`, `smtpEnhancedStatus`가 있다.
SMTP 응답 선두에서 기본 코드와 일치하는 상세 코드를 확인했을 때만 이를 기록한다. 관리자 로그 목록의 요약과 Slack에
확인한 코드가 표시되며, 관리자 목록은 알려진 상세 코드의 의미를 한국어로 보여준다.
예외 메시지와 스택, 수신 주소, 인증번호와 토큰은 기록하거나 Slack으로 보내지 않는다.
Slack 알림은 환경별 서버 오류 채널 설정을 공유한다. SMTP 수락과 수신함 도착은 별개다.
