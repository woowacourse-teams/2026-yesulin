# 공연사 일정 소유권과 명단

- ownerId가 있으면 계정 일정이다. 관리 열쇠는 null이며 익명 API에서도 owner 일정을 제외한다.
- 생성 시 회원 행을 잠그고 `(owner_id, creation_key)`로 재시도를 재사용한다. 다른 키로 여러 일정을 만든다.
- 준비 상태는 시간 칸 0개, slotMinutes/slotCapacity 0이다. 익명 일정 생성의 필수 날짜 검증은 유지한다.
  자유 배정은 배우의 기존 slot_date/slot_start_time에 저장하며 시간 칸 생성·확정 API를 노출하지 않는다.
- 가져오기/수정/제외는 소유 일정 행을 잠그고 READ_COMMITTED로 실행한다. 지원자 행도 ID 순으로 잠근다.
  같은 일정에서 출처 ID와 입력한 전화번호는 각각 유일하고 전체 최대 300명이다.
- 같은 출처는 기존 값을 보존하고 건너뛴다. 새 출처 중 하나라도 잘못되면 전체 요청을 롤백한다.
  다른 일정에는 같은 출처를 등록할 수 있다. 제외한 출처는 다시 가져올 수 있다.
- 빈 전화는 null, 이메일은 빈 문자열이다. 입력한 전화는 기존 휴대폰 형식으로 검증한다.
  이름·연락처는 담당자 확인 스냅샷, 배역과 출처 연결은 서버가 결정한다.
- 수정은 기존 이름·전화·이메일을 비교해 다른 화면의 수정을 덮어쓰지 않는다. 제외는 원본 심사에 전파하지 않는다.
- 원본·대상 소유권을 각각 검사한다. no-store, 세션+CSRF를 적용하고 개인 정보/열쇠를 URL·분석·영구 브라우저 저장소에 넣지 않는다.
- owner 초안에서는 관리 링크 문자와 배우 안내 큐를 생성하지 않는다. 후속 확정·발송 구현 전에는 설계안의
  원본 판정 변경/기존 미발송 보류 경계를 구현해야 한다.

## 자유 날짜·시간 배정

- 공연사 소유 일정 행 잠금과 READ_COMMITTED를 유지한다. 같은 일정의 서로 다른 배우 1~300명만 받는다.
- 시간 칸/정원/미래일 제한 없이 날짜(1000~9999년)와 분 단위 시작 시각을 저장한다. 기준은 Asia/Seoul이다.
  같은 날짜·시각에 여러 명을 배정할 수 있다. 날짜·시각 둘 다 없는 null은 해제이고 일부 누락은 오류다.
- 입력 전 slot과 현재 slot을 비교해 낡은 수정을 거절한다. 이미 요청 slot이면 재시도 성공이다.
  전체 트랜잭션으로 저장해 한 명의 충돌·잘못된 값·소속 오류라도 일부 저장하지 않는다.
- 연락처 수정·출처 재등록은 배정을 유지한다. 원본 판정/메모는 변경하지 않고 판정 변경 경고를 유지한다.
  명단에서 제외하면 그 행의 배정도 제거된다. 초대 시각·메시지 큐를 만들지 않는다.
