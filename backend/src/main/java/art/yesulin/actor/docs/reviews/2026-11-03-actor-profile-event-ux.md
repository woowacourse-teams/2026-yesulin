## 구현과 실행 근거

- `NotebookHeader`의 배우 계정 링크를 `/applicants` 마이페이지로 변경했다. 내 지원서 메뉴는 배우 영역에 유지한다.
- `ProfileEditor`는 기본정보→사진→배우 페이지를 먼저 안내하며 추가정보·영상은 선택 메뉴로 둔다.
  `ProfileInformationSection`은 공개에 필요한 이름·생년월일·성별부터 보여 주고 나머지는 native details로 펼친다.
  기본정보 저장률을 필수 작성률로 표현하던 문구/계기를 정리했다.
- `save(nextTab)`는 실제 프로필 저장 성공 뒤 이동한다. ref로 요청 중 연속 클릭을 차단하며,
  다음 단계 저장이 실패하면 입력을 유지한다. PDF 저장 이벤트는 종전과 같이 API 성공 뒤에만 호출한다.
- 접힌 정보에 오류가 있으면 해당 details를 펼치고 입력란에 초점을 옮긴다.
- 사진 목록은 모바일에서 작은 이미지와 버튼을 나란히 둔다. 페이지 설정 안에서 앞뒤 이동·대표 지정을 제공한다.
  비공개 사진은 대표 지정 대상으로 자동 공개하지 않는다. 같은 보관함 순서를 공유한다는 설명을 둔다.
- 공개 설정에서는 아이디와 사진을 먼저 보여 주고 공개할 나머지 항목·영상은 접어 둔다.
  사진 아래에 미리보기·공개 버튼을 두고, 부족한 항목 안내는 입력 위치로 연결한다.
- 미저장 프로필/아이디는 공개·미리보기를 차단한다. 정상 일반 저장의 최초 공개 안내도
  저장 응답 전후 새로 작성한 내용이 없을 때만 열고 표시 기록을 남긴다.
- 미리보기 복귀 링크를 모바일에서 숨기는 공통 heading-action 밖으로 이동했다.
- 처음 등록하는 상황을 재현할 `?mockApplicantProfile=empty`를 `/dev/scenarios`와 목 문서에 연결했다.
  첫 조회에서만 초기화하며 이후 작성값은 유지한다는 회귀 테스트를 포함한다.
- 새 의존성·파일 업로드 API·공개 조건·동의 문구·분석 이벤트 의미 변경은 없다.
