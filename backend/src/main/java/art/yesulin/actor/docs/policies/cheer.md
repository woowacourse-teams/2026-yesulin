# 배우 페이지 좋아요

로그인한 배우 계정이 다른 배우의 페이지(공개 프로필)에 보내는 반응을 `actor`의 `cheer` 하위 패키지가 맡는다. 지금은 좋아요만 있다.
제품 규칙은 [공통 도메인](../../../../../../../../../docs/domain.md#배우-페이지), HTTP 계약은
[백엔드 API](../../../../../../../../docs/api.md#배우-페이지-좋아요--3개)가 정본이다.

## 경계와 이름

- 팬과 배우를 별도 모듈로 나누지 않는다. 같은 회원이 다른 배우의 페이지에서는 반응을 보내는 쪽이고 자기 페이지에서는 주인이므로,
  구분은 모듈이 아니라 대상 페이지의 주인인지로 한다.
- 엔티티 이름은 `ActorPage` 계열을 따른다(`ActorPageLike`, 테이블 `actor_page_likes`).
- `cheer`는 `page`의 도메인 객체(`ActorPage`)에 의존하지만 `page`는 `cheer`를 알지 못한다. 공연사의 관심 배우(`bookmark`)와
  같은 방향이다.

## 구현 정책

- 페이지는 아이디가 바뀔 수 있으므로 `publicId`로 찾고 `actor_pages.id`를 참조한다.
- 목록에 보이는 페이지(공개 중이고 잠기지 않음)만 받고, 그 밖은 존재 여부를 알 수 없도록 공개 조회와 같은 `ACTOR_PAGE_NOT_FOUND`다.
- 공개 배우 페이지 응답은 보는 사람과 무관하게 같아야 하므로 좋아요 수와 내 상태는 별도 API가 세션을 읽어 준다. 이 응답은 캐시하지 않는다.
- 쓰기는 회원 행을 먼저 잠그고 존재 확인 뒤 저장해 같은 요청을 반복해도 하나만 남긴다. 유일 제약은 마지막 방어선이다.
- 내 페이지에 누를 수 없다는 규칙은 `ActorPageLike.of`가 지키고, 화면 숨김에 의존하지 않는다.
- 누른 회원을 응답이나 로그에 노출하지 않는다.
