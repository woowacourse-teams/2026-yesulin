# 배우 페이지 응원

활성 일반 회원이 다른 배우의 페이지(공개 프로필)에 보내는 반응을 `actor`의 `cheer` 하위 패키지가 맡는다. 지금은 좋아요와 응원 글이
있다. 제품 규칙은 [공통 도메인](../../../../../../../../../docs/domain.md#배우-페이지), HTTP 계약은
[좋아요](../../../../../../../../docs/api.md#배우-페이지-좋아요--3개)와
[응원 글](../../../../../../../../docs/api.md#배우-페이지-응원-글--4개)이 정본이다.

## 경계와 이름

- 팬과 배우를 별도 모듈로 나누지 않는다. 같은 회원이 다른 배우의 페이지에서는 반응을 보내는 쪽이고 자기 페이지에서는 주인이므로,
  구분은 모듈이 아니라 대상 페이지의 주인인지로 한다.
- 엔티티 이름은 `ActorPage` 계열을 따른다(`ActorPageLike`, `ActorPageCheer`, 테이블 `actor_page_likes`, `actor_page_cheers`).
- `cheer`는 `page`의 도메인 객체(`ActorPage`)에 의존하지만 `page`는 `cheer`를 알지 못한다. 공연사의 관심 배우(`bookmark`)와
  같은 방향이다.
- 보는 사람의 자격(로그인 여부, 주인 여부, 참여 가능 여부)은 `ActorPageParticipant`, 목록에 보이는 페이지 판단은
  `ListedActorPageFinder`가 맡아 좋아요와 응원 글이 같은 기준을 쓴다.

## 구현 정책

- 페이지는 아이디가 바뀔 수 있으므로 `publicId`로 찾고 `actor_pages.id`를 참조한다.
- 목록에 보이는 페이지(공개 중이고 잠기지 않음)만 받고, 그 밖은 존재 여부를 알 수 없도록 공개 조회와 같은 `ACTOR_PAGE_NOT_FOUND`다.
- 공개 배우 페이지 응답은 보는 사람과 무관하게 같아야 하므로 좋아요 수, 응원 글과 내 상태는 별도 API가 세션을 읽어 준다. 이 응답은 캐시하지 않는다.
- 내 페이지에 좋아요·응원 글을 쓸 수 없다는 규칙은 `ActorPageLike.of`와 `ActorPageCheer.write`가 지키고, 화면 숨김에 의존하지 않는다.
- 작성 회원은 응답이나 로그에 노출하지 않는다. 응원 글 작성자는 팬 번호와 내 글 여부로만 드러난다.

### 좋아요

- 쓰기는 회원 행을 먼저 잠그고 존재 확인 뒤 저장해 같은 요청을 반복해도 하나만 남긴다. 유일 제약은 마지막 방어선이다.

### 응원 글

- 팬 번호는 저장하지 않고 읽을 때 계산한다. `ActorFanNumbers`가 그 페이지에서 회원별 가장 이른 응원 글 ID 순서(삭제한 글 포함)로
  번호를 매기므로, 같은 회원은 같은 번호를 쓰고 글을 지워도 번호가 바뀌지 않는다.
- 삭제는 `deleted_at`만 남기는 방식이고 목록·글 수에서는 빠진다. 지운 글이나 남의 글은 수정·삭제할 수 없다.
- 목록은 글 ID 기준 커서(`before`)로 최신순 조회한다. 쓰기에는 잠금이 없고, 같은 내용을 두 번 보내는 것은 화면이 전송 중 버튼을
  막아 줄인다. 서로 다른 회원의 글이 동시에 쓰이면 응답의 팬 번호가 잠시 어긋날 수 있고 다시 읽으면 바로잡힌다.
- 수정과 삭제는 글 행을 잠가 읽고 처리해, 겹쳐 보내도 지운 글이 되살아나지 않는다.
- 신고, 운영자 삭제, 도배 제한은 구현하지 않았다. 필요한 정책은 `docs/pending-decisions.md`에서 정한다.
