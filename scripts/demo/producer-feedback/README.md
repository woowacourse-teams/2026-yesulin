# 공연사 피드백용 로컬 데모 시드

공연사 심사 흐름을 시연하기 위한 공연 1개, 공고 1개, 지원자 233명을 로컬 MySQL에 생성한다. 포스터와 지원자
사진은 로컬 LocalStack S3에만 업로드한다. 일반 애플리케이션 시작과 Flyway 마이그레이션에서는 실행되지 않는다.

## 실행

저장소 루트에서 로컬 통합 환경을 먼저 실행한다.

```bash
docker compose up -d --build --wait
./scripts/demo/producer-feedback/seed.sh
```

지원자 심사 화면의 주요 식별자는 다음과 같다.

- 공연 ID: `980000`
- 공고 공개 ID: `98000000-0000-4000-8000-000000000001`
- `서연` 배역 ID: `980001` — 지원자 233명
- `지우` 배역 ID: `980002` — 복수 지원자 58명
- 대표 지원자: `김예술`, 지원서 DB ID `981001`
- 지원자 233명은 성별에 맞춘 데모 YouTube 영상 링크를 하나씩 가진다.
- 지원자 233명은 모두 1차 심사 `검토 대기` 상태로 시작한다.
- 기본 심사 목록은 `서연` 배역 조건에 맞는 여성 만 20~35세 지원자가 먼저 표시된다.

제작사 로그인 계정은 로컬에서만 사용한다.

- 이메일: `local-producer@yesulin.art`
- 비밀번호: `local-producer-demo-2026`

데이터만 확인하거나 삭제할 수 있다.

```bash
./scripts/demo/producer-feedback/seed.sh verify
./scripts/demo/producer-feedback/seed.sh reset
```

`seed`를 다시 실행하면 기존 데모 데이터만 삭제한 뒤 같은 값으로 다시 생성한다.

## 사진 넣기

`assets/applicants`에 다음 규칙으로 `jpg`, `jpeg`, `png`, `webp` 파일을 넣는다. 성별·나이형 파일은
파일명 순서대로 1번 지원자부터 연결한 뒤, 233명까지 같은 순서로 순환 연결한다. 파일명에 적은 성별과 나이를
해당 지원자 데이터에 반영한다.

```text
man_25.png       # 25세 남성
man_25_2.png     # 같은 성별·나이의 두 번째 사진
woman_26.jpg     # 26세 여성
woman_27_3.png   # 같은 성별·나이의 세 번째 사진
```

- 성별은 `man`, `woman`으로 작성한다.
- 나이는 만 나이 숫자로 작성한다.
- 같은 성별·나이의 사진은 `_2`, `_3`처럼 구분한다.
- 파일 정렬 순서가 지원자 번호가 되므로 파일명은 중복되면 안 된다.
- 모든 사진은 지원자의 프로필 사진 한 장으로 연결된다.
- 사진이 없어도 지원자 데이터는 생성된다.
- 사진을 추가하거나 교체한 뒤 `seed.sh`를 다시 실행하면 LocalStack과 DB 연결이 갱신된다.
- `assets/poster.jpg|jpeg|png|webp`를 두면 데모 포스터로 사용한다. 없으면 저장소의 기존 공연 이미지를 사용한다.

실제 배우 사진은 동의 없이 사용하지 않는다. 사용 허락을 받은 사진, 라이선스가 허용된 스톡 사진 또는 가상 인물
사진만 둔다.

## 운영 차단

스크립트는 다음 조건을 모두 만족해야 실행된다.

- Compose 프로젝트 이름이 `yesulin-local`
- Compose의 `mysql`, `localstack` 서비스가 실행 중
- MySQL 컨테이너의 DB 이름이 `yesulin`
- 로컬 제작사 계정 `9001`이 존재

운영 DB 주소나 운영 S3 자격증명을 입력받지 않으며, 배포 시작 과정에서도 이 스크립트를 호출하지 않는다.
