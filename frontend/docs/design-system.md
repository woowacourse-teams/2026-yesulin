# 디자인 시스템

구현의 최종 기준은 `src/app/globals.css`, `src/app/interactions.css`와 `src/components/ui/`다.

## 원칙

- 한 영역의 핵심 행동만 `brand`로 강조한다.
- 상태는 색만으로 표현하지 않고 텍스트·배지·아이콘을 함께 사용한다.
- 배우 화면은 안내와 단계 진행, 기획사/제작사 화면은 비교·검색·빠른 검토를 우선한다.
- 같은 책임의 요소는 같은 spacing, 높이, radius와 정렬 축을 사용한다.
- 시각 변경으로 기존 기능이나 정보 위계를 제거하지 않는다.

## 핵심 토큰

| 역할 | 값·token |
| --- | --- |
| Primary | `brand #246BFE`, hover `brand-strong`, active `brand-pressed` |
| Canvas | `surface #F7F9FC` |
| Card | `background/card #FFFFFF` |
| Text | `foreground #111722`, `muted-strong`, `muted` |
| Border | `border #E2E8F0`, `border-soft #F1F5F9` |
| Pass | green / `pass-bg` |
| Fail | red / `fail-bg` |
| Etc | violet / `etc-bg` |
| Pending | neutral slate |
| Producer sidebar | `sidebar #0B1018` 계열 |

현재 심사 상태에 `ABSENT`는 없다. 새 UI도 `PENDING`, `PASS`, `FAIL`, `ETC`만 표현한다.

## 기본 크기

- spacing은 4px 체계를 우선한다.
- 모바일 일반 좌우 여백 20px, 관리자 16px, 데스크톱 24~32px
- control 최소 높이 44px, 일반 input 48px. 공통 필드는 `aria-invalid=true`일 때 오류 테두리와 포커스를 표시한다.
- `rounded-control` 12px, `rounded-card` 16px, `rounded-modal` 24px
- 일반 카드는 shadow보다 배경·여백·1px border로 구분한다.
- 숫자·날짜·통계에는 `.num`을 사용한다.

## 포커스와 입력 상태

- 버튼·링크·탭·펼침 버튼은 키보드 탐색 시 기본 2px 외곽선과 2px 간격을 사용한다. 클리핑되는 카드·표 내부만 필요한 안쪽 간격을 유지한다.
- 일반 입력·선택·긴 글 입력은 1px 브랜드 테두리와 1px 브랜드 ring을 합쳐 한 겹으로 표시한다. 공통 `fieldControlClass`를 우선 사용한다.
- 오류 입력은 같은 두께의 fail 색과 오류 문구를 함께 유지한다. 활성 탭·선택 상태·오류 상태를 포커스 테두리로 대신하지 않는다.
- 아이디의 @ 표시·검색처럼 하나로 묶인 입력은 바깥 컨테이너만 강조하고 내부 input에는 외곽선을 겹치지 않는다.
- 공개 화면에서 별도 굵은 포커스 규칙을 추가하지 않는다. 스킨의 기본 입력 스타일은 components 레이어에 두어 공통 컨트롤 유틸리티를 덮지 않는다.

## 접근성과 반응형

- 아이콘 버튼은 접근 가능한 이름과 44×44px hit area를 제공한다.
- 활성 navigation은 `aria-current`, 토글은 `aria-pressed`를 사용한다.
- 필드 오류는 control과 연결하고 구체적인 복구 문구를 표시한다.
- 잘못된 항목이 여럿이면 한 번에 모두 표시하고, 입력을 마칠 때 해당 항목만 다시 검사한다.
- 모바일에서 hover에만 기능을 숨기지 않는다.
- fixed 하단 영역은 safe area를 반영한다.
- reduced motion에서는 transition과 animation을 제거한다.

## 공개 서비스 화면

- 로고는 슬로건 없는 워드마크 `public/images/yesulin-wordmark.png`를 쓰고, 탭·앱 아이콘은 워드마크의 파란 ㅇ을 쓴다. 원본 SVG를 받기 전 임시 PNG다.
- 모든 영역의 예술in 로고는 서비스 메인 `/`으로 이동한다. 영역별 홈은 별도 메뉴로 접근한다.
- 공고 상세는 기본 정보 → 첨부파일(있을 때) → 공고 본문 → 공연사 순서로 읽는다.

- 홈·오디션 목록/상세·무료 공연·소개·인증·정책 문서·배우 화면·일정표 생성은 `.public-notebook`의 흰 배경 토큰과
  `NotebookHeader`·`NotebookFooter`를 공유한다. 운영자 화면의 기본 토큰에는 적용하지 않는다.
- 공개 화면과 공개 모달은 Wanted Sans Variable을 사용하고, 글꼴 조회 실패 시 기존 시스템 글꼴로 표시한다.
  홈과 공개 목록의 제목 옆에는 장식적인 부연 설명을 붙이지 않는다.
- 커뮤니티 목록(`/community`)은 공통 헤더 아래 최대 1160px의 3단 구성이다. 왼쪽은 ‘배우 수다방’ 제목(주아체·하늘색 밑줄)과 소개·내 알림·이용 안내, 가운데는 별 캐릭터 글쓰기 카드와 주제 필터(전체와 5개 주제), 작성자 옆 주제 칩이 있는 글 목록이다. 필터는 URL에 남고 좁은 화면에서 가로로 넘긴다. 오른쪽은 ‘지금 인기 글’과 ‘마감 임박 공고’ 순이다. 인기 글은 제목을 누르면 상세로 이동하며, 비거나 조회에 실패하면 해당 카드만 숨긴다. 1100px 이하에서는 소개가 위로 올라가고, 860px 이하에서는 한 단으로 쌓여 마감 공고가 목록 아래에 온다. 상세와 작성 화면은 600px 중앙 단을 쓴다.
  사진이 없는 작성자는 별 캐릭터를 색만 바꿔 보인다. 색은 글 번호와 표시 이름으로 정해 같은 글 안의 같은 작성자는 같은 색이고, 계정 정보는 쓰지 않아 다른 글의 같은 사람과 이어지지 않는다.
  글·댓글의 수정·삭제·신고·링크 복사는 ⋯ 버튼의 바텀시트(`dialog`)로 모으고 삭제는 시트 안에서 한 번 더 확인한다.
  커뮤니티 글쓰기의 제목·본문에는 보이는 라벨과 테두리를 둔다. 글 등록은 폼 우측 하단의 별 캐릭터와 ‘올리기’ 문구가 있는 직사각형 버튼으로 한다. 작성할 때마다 익명 체크를 바꿀 수 있다. 공개 페이지가 없는 배우가 익명을 해제하면 설정 링크를 보여 주고 공개 등록만 제한한다. 글쓰기 폼은 프로필 미리보기를 생략한다. 원댓글 우측의 ‘대댓글’을 누르면 입력칸이 맨 아래가 아니라 그 댓글 묶음 바로 아래에 열리고, 대댓글은 원댓글 아래 들여쓴 연회색 영역에 묶는다. 원댓글이 아직 불러와지지 않았으면 맨 아래 입력칸을 쓴다.
  상세의 댓글 입력은 목록 아래 테두리 있는 입력칸에 배치하고 Enter로 보낸다(Shift+Enter 줄바꿈).
- 배우 화면은 공통 헤더 아래 밑줄 메뉴로 마이페이지·내 지원서·내 프로필을 전환한다. 모바일도 같은 메뉴를 쓰며
  별도 하단 고정 메뉴는 두지 않는다. 마이페이지는 밝은 프로필·보관함 카드와 최근 제출 내역을 보여 준다.
- 공개 배우 프로필은 901px 이상에서 왼쪽 대표 사진·사진 카드 목록과 오른쪽 기본 정보·자기소개·영상·경력 카드로 나눈다.
  왼쪽 사진 영역은 상단 헤더 아래에 붙어 스크롤을 따라오며, 화면 높이보다 길면 사진 영역 안에서 스크롤할 수 있다.
  좁은 화면에서는 사진 다음에 정보를 한 열로 읽는다. 값이 없는 선택 항목은 카드 자체를 생략한다.
  대표 사진과 사진 카드는 클릭·키보드로 공통 확대 뷰어를 연다. 대표 사진의 중복 주소를 제외하고 이전·다음과
  좌우 방향키로 넘기며 맞춤 보기·2배 확대를 제공한다. Escape로 닫으면 원래 사진 버튼으로 초점이 돌아간다.
  사진이 없으면 대체 이미지를 보이고 확대 버튼은 만들지 않는다. 본인·운영자 미리보기에도 같은 배치를 쓴다.
- 일정표 생성은 작품·담당자 정보와 날짜·시간 폼 옆에 실제 설정으로 계산한 요약을 둔다. 잘못 입력한 설정의 시간 칸·최대 인원은
  숫자를 추정하지 않고 —로 표시한다. 모바일에서는 폼 다음에 요약과 생성 버튼을 배치한다. 관리 링크·배우 확인 화면의 레이아웃은 별도다.
- 본문 상한은 1200px, PC 좌우 여백은 최소 64px, 760px 이하에서는 20px이다.
  공고 상세의 공고·공연사 영역도 1200px 상한을 쓰고, 인증 폼은 480px 상한을 별도로 둔다.
- 1080px 이하 헤더는 로고와 메뉴 버튼 한 줄이다. 메뉴는 버튼·Escape·바깥 클릭·링크 선택으로 닫히며,
  열림 상태를 `aria-expanded`로 알린다. 상단은 오디션·무료 공연·이벤트이며, 소개·FAQ 링크는 푸터에 둔다.
- 섹션 제목은 `오디션 공고`, `무료 공연`, `자주 묻는 질문`처럼 내용을 직접 적는다.
  장식용 섹션 번호와 링크 끝의 화살표는 사용하지 않는다. 배너를 넘기는 탐색 표시는 이미지 안쪽 양옆에 두고, 선택 표시는 이미지 하단 가운데에서 짙은 배경과 밝은 표시로 구분한다. 새 창 안내는 접근 가능한 이름으로 제공한다.
- 공개 화면의 공통 아이콘은 React Icons의 Phosphor의 선 아이콘을 `components/ui/site-icon.tsx`로 제공한다.
  아이콘 자체는 보조기술에서 숨기고 버튼에는 별도의 이름을 붙인다. 소셜 서비스 로고는 각 브랜드 표시를 유지한다.
- 캐릭터·노트 표현은 배너에 사용하고, 목록 본문과 폼에는 담백한 배경·선·간격을 사용한다.
- 홈·오디션 목록의 공고 카드와 홈 무료 공연 카드는 테두리 없는 3:4 포스터 카드다. 오디션 목록은 760px 이하 2열, 761~1099px 4열,
  1100px 이상 6열로 표시한다. 홈은 가로로 넘기는 포스터 줄이며 1100px 이상 5장, 태블릿 4장, 모바일 2.3장이 보인다.
  데스크톱은 줄 양옆 버튼, 모바일은 스와이프로 넘긴다. 이미지는 잘리지 않게 담고 남는 여백은 같은 이미지를 흐리고 어둡게 깔아 채운다.
  세로가 가로의 1.8배를 넘는 긴 공고문만 윗부분부터 채워 보여 준다. 이미지 없는 공고는 분야별 로고 계열 그라데이션 위에 분야 실루엣과 로고 반짝이를 두고 작품명을 크게 쓴 기본 포스터를 쓴다. 작품명은 띄어쓰기 단위로만 줄을 바꾸고 줄 길이를 고르게 맞춘다. 기본 포스터의 반짝이는 카드가 처음 화면에 60% 이상 들어올 때 크기 그대로 한 바퀴(1.1초) 돌며 오른쪽 위 긴 꽃잎 끝만 금빛으로 물들었다 돌아오고, 마우스를 올릴 때 한 번 더 돈다(뗄 때는 돌지 않는다). 마우스를 올리면 이미지 포스터처럼 앞면이 1.03배 커지고, 터치 화면은 누르는 동안 카드가 0.98배로 작아진다. 움직임 줄이기 설정에서는 돌지도 크기가 바뀌지도 않는다.
  마감 상태는 포스터 왼쪽 위 배지 글자로 표시하고, 제목 2줄·분야와 작성자·페이·게시일·조회·첨부를 아래에 둔다.
  이벤트 목록도 같은 포스터 카드를 쓰되 항목이 적어 2열(≤760px)·3열·4열(≥1100px)로 크게 보이고, 진행 상태·신청 마감을 배지로 표시한다.
  공연 목록(`/shows`)과 홈 무료 공연 줄은 같은 3:4 공연 포스터 카드(`ShowPosterCard`)를 쓴다. 목록은 2열(≤760px)·3열·4열(≥1100px)이고,
  예매 중인 공연은 다음 회차 일시를 제목 위에 파란색으로 강조한다. 장르 필터는 회색 알약 버튼이다.
- 분야는 회색 알약 탭(`.notebook-category-tab`, 선택 시 검정), 모집 상태와 장르는 `.notebook-filter`를 사용한다. 주소 이동은 `aria-current`, 화면 내 선택은 `aria-pressed`로 구분한다.
  홈은 별도 분야 바로가기와 포스터 줄별 전체 보기 링크를 제공한다. 모집 상태·정렬·하단 전체 공고 보기 버튼은 두지 않는다.
  목록은 분야 탭과 모집 상태를 같은 행 좌우에 놓고, 다음 행에 정렬을 왼쪽·검색을 오른쪽으로 배치한다. 좁은 화면에서는 줄바꿈한다.
  목록 제목은 모바일 22px, 데스크톱 29px을 사용하고, 카드·인증 패널은 `rounded-card`, 필터·입력은 `rounded-control` 토큰을 사용한다.
- 공개 화면 글자색은 무채색 3단계(`#191F28`·`#4E5968`·`#6B7684`)이고, 페이지·섹션 제목은 굵기 800, 자간 -0.03em이다. 카드 안 공고 제목은 700이다.
- 홈 분야 바로가기는 흰 배경 위 회색 둥근 타일 아이콘이다. 강조 장면의 색은 로고의 하늘·보라를 쓰고, 동작 감소 설정에서는 장면 없이 색만 바뀐다.
- 공개 화면의 portal 모달에는 `.public-theme`을 적용해 페이지와 같은 토큰을 사용한다. 이 클래스는 전체 페이지 높이를 강제하지 않는다.
- 공개·배우 화면의 작은 상태 텍스트는 pass `#15803d`, warn `#a15c07`로 대비를 확보한다.
  배우 화면은 `.applicant-theme`으로 범위를 제한하며, 운영 화면의 상태 토큰은 유지한다.
- 배우 화면과 지원서는 한국어 단어를 유지하되 긴 문자열을 줄바꿈한다. 상세 화면의 공연명·공고명은 전체 내용을 보여 준다.
- 지원서 단계가 바뀌면 제목으로 포커스를 옮기고, 가로 단계 목록에서 현재 단계를 보이게 한다. 필드 오류가 있으면 기존 첫 오류 항목 이동을 따른다.
- 정책 문서는 데스크톱 고정 목차와 모바일 접이식 목차를 제공한다.
- 공개 헤더의 hover와 현재 메뉴는 글자색·밑줄로 표시한다. FAQ 배너는 별도 hover 장식을 추가하지 않고 링크·포커스를 유지한다.
- 공개 푸터는 헤더 메뉴를 반복하지 않고 서비스 소개·FAQ·카카오톡 문의·공고 알림 링크만 한 줄에 둔다. 내용이 짧은 화면에서도 화면 아래에 붙는다.
  PC 푸터는 브랜드 소개와 선택·복사할 수 있는 이메일 주소를 함께 표시한다. 760px 이하에서는 로고·슬로건·이메일을 숨기고
  도움말 링크와 정책 링크·저작권만 남긴다. 푸터 글자는 13px 이상, 링크 높이는 44px 이상이다. 동의문은 지원서 전문 보기로 연결하고 공개 푸터에서는 처리방침과 이용약관을 안내한다.
- 공연 목록은 `status=CLOSED`이거나 미래 회차가 없는 공연을 예매 마감 구역에 두고, 마감 문구와 낮춘 이미지 톤으로 표시한다.
  미래 회차가 남아 있어도 수동 마감 상태를 우선한다. 홈은 예매 중 공연부터 보여 준다. 관리 화면은 예매 마감과 공연 숨김을 별도 버튼으로 제공하며,
  숨김 해제 시 마감 상태 유지 또는 시작 전 회차의 예매 재개 여부를 안내한다.
  목록에는 잔여석이 없으므로 매진 여부를 추측하지 않으며 회차별 예매 가능 여부는 상세에서 확인한다.

## 화면 상태와 정렬

- 공개 목록의 빈 상태와 없는 상세는 `ContentState`의 제목·설명·선택적 다음 행동을 사용한다. 로딩은
  `ContentSkeleton`의 상태 안내와 동작 감소 설정을 공유하고 내부 모양은 콘텐츠에 맞춘다.
- 공개 상세의 실제 404는 브랜드 헤더·푸터와 목록 복귀를 제공한다. 조회 장애는 재시도를 제공하며 404로 표시하지 않는다.
- 공연 상세·완료·오류는 공개 목록과 같은 기본 여백을 사용한다. 모바일 예매 바의 safe area와 확인 카드의 읽기 폭은 유지한다.
- 공연 포스터·이벤트 이미지의 로드 실패는 대체 아이콘으로 표시하고, 공고 썸네일은 분야별 기본 그림으로 돌아간다.
- 이벤트 상세는 PC에서 목록 복귀 링크와 본문을 같은 중앙 영역에 둔다. 대표 이미지가 있으면 최대 1000px의 두 열, 없으면 최대 760px의 한 열을 사용한다. 이미지는 원래 비율을 유지하고 모바일은 세로 읽기 순서를 유지한다. 하단에는 선택적인 상세 설명과 순서가 있는 상세 이미지를 표시한다.
- 이벤트 상세의 대표·상세 이미지는 클릭·키보드로 확대 뷰어를 열 수 있다. 맞춤 보기·2배 확대를 제공하고 닫으면 이미지 버튼으로 초점을 돌린다.
- 이벤트 대표 이미지는 스크롤을 따라 고정하지 않는다. 참가 신청서의 명함 소개는 가상 프로필 사진이 들어간 고정 양면 예시를
  항상 보여 준다. ‘무료 프로필 명함 제작 이벤트’와 ‘무료 명함 만들기’ 버튼으로 혜택을 강조하고, 제작 선택 후에만 취소를 제공한다.
  명함 정보 입력·수정은 별도 모달에서 진행하고,
  닫았다 다시 열어도 작성 내용과 사진을 유지한다. 업로드 중에는 모달을 닫지 않는다.
  모달에서는 이름·이메일·SNS·생년월일·사진·분야·경력을 미리보기에 바로 반영한다. PC에서는 입력 영역 옆에서 미리보기를
  유지한다. 1024px 미만에서는 화면 전체를 쓰고 ‘정보 입력 / 명함 미리보기’ 탭으로 전환한다. 입력 중에는 미리보기를 숨기고
  다시 입력으로 돌아올 때 작성 내용과 스크롤 위치를 유지한다. 상단 닫기와 하단 전체 너비 완료 버튼에 safe area를 반영하고,
  보이는 화면 높이가 바뀌면 키보드 위에서 입력 영역을 스크롤할 수 있게 맞춘다.
  SNS는 인스타그램·스레드·유튜브 중 하나와 20자 이하 계정명·채널명을 함께 받으며 둘 다 비울 수 있다. 링크는 받지 않는다.
  입력 항목에 맞춰 앞·뒷면을 전환하며 휴대폰 번호는 표시하지 않는다.
  명함은 고정 비율로 표시하고 분야는 줄바꿈하며, 긴 내용은 글자 크기를 맞춰 생략 없이 표시한다.
  개인정보 동의 체크는 PC에서 신청 버튼 왼쪽에, 모바일에서는 버튼 위에 둔다. 수집·이용 상세는 기본 접힘으로 제공한다.
  신청 전 안내 팝업은 이벤트별 관리자 설정을 따른다.
- 배우 홈·프로필·지원서 목록과 일정표 생성은 메인 헤더와 같은 1200px 상한으로 정렬한다. 프로필은 항목 메뉴와 입력 폼,
  일정표 생성은 입력 폼과 요약을 나란히 두고 모바일에서는 한 열로 배치한다.
- 프로필 작성은 기본정보·사진·배우 페이지를 먼저 안내하고 추가정보·영상은 선택 메뉴로 분리한다.
  사진 추가·공개 범위·지원서/페이지 대표사진·순서 조작은 사진 탭에 모은다.
  입력/페이지 미리보기 전환은 폼을 유지하며, 1101px 이상에서는 나란히 표시하고 좁은 화면에서는 한쪽씩 표시한다.
  미리보기는 공개 범위가 적용된 저장본이고, 공개 API 성공 후 완료 화면에 링크·QR·공유를 표시한다.
  모바일 사진은 작은 이미지와 조작 버튼을 나란히 두고 모든 순서 조작에 44px 이상의 앞뒤 버튼을 제공한다.
  프로필 편집의 모바일 입력 글자는 16px로 유지한다. 저장·공개 순서는 [배우 작성·공개 흐름](../../backend/src/main/java/art/yesulin/actor/docs/flows/profile-setup.md)을 따른다.
- 공개 배우 페이지의 문의 버튼은 이름·기본정보 안에 두며 자기소개·영상 앞에 별도 안내 카드를 쌓지 않는다.
  공개된 SNS·외부 링크는 기본정보 아래·문의 위에 배치한다. SNS는 브랜드 아이콘, 일반 사이트는 링크 아이콘과 호스트 이름을 표시하며
  하단에 주소를 반복하지 않는다. 링크가 없으면 영역을 생략하고 44px 조작 영역과 서비스 이름·새 창 안내를 제공한다.
  본문 구역은 구분선과 여백으로 나누고 긴 자기소개는 세 줄 후 펼친다. 실제로 넘치는 소개에만 펼침 버튼을 제공한다.
- 공개 상태의 명칭은 ‘숨김’, 상태를 바꾸는 행동은 ‘숨기기 / 다시 공개’로 맞춘다.

## PDF 지원서 심사

- 원본 PDF 전체 페이지를 PDF.js로 이어서 표시한다. 페이지 선택·이동·다운로드·새 창·일반 새로고침 도구는 두지 않는다. 실패한 부분에서만 재시도한다. 화면 가까운 페이지만 직렬 렌더링하고 먼 페이지 bitmap은 해제한다.
- 상단은 심사함 경로·전체/판정 완료 수, 배역 필터와 PDF 추가, 판정 탭과 보기 전환 순서다. 개별 지원서 제목은 항상 입력 가능하고 이전/다음은 지원서를 이동한다. 원본 파일명과 PDF 배지는 표시하지 않는다.
- 데스크톱에서는 원본 옆에 배역 드롭다운·내부 메모·합격/보류/불합격을 두고, 모바일에서는 원본 아래에 둔다. 추출된 사진·경력으로 원본을 재구성하지 않는다.
- 제목·메모는 입력 중단·blur 시 자동 저장하고 저장 상태를 간결하게 표시한다. 이동·판정 전에 저장 성공을 기다리고 실패한 입력을 보존한다. 수동 메모 저장·대기 복원 버튼과 반복 설명은 두지 않는다.
- 기본 너비는 뷰어에 맞춘다. 일반 휠은 스크롤, Ctrl/Cmd+휠·트랙패드 핀치는 확대하며 키보드 확대도 지원한다. 원본 여백·배치·이미지는 PDF 자체 표현을 유지한다.
- 업로드 내역·오류·재시도 알림은 유지한다. 연락처·일정 화면에서는 알림을 본문 상단에 배치해 저장 도구를 가리지 않는다. 완료 알림을 지워도 서버 지원서·심사 결과는 삭제하지 않는다.
