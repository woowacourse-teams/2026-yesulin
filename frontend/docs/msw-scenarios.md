# MSW 시나리오

MSW는 `NEXT_PUBLIC_API_MOCKING=enabled`에서만 실행하며 `/dev/scenarios`에서 대표 상태를 연다. 경로와 데이터는
프론트 UI 검증용이며 백엔드 계약의 정본이 아니다.

## 공개 공고 정렬

`/`·`/auditions`에서 최신순과 마감 임박순을 선택한다. 오래된 글이지만 내일 마감하는 공고가 있어 정렬 변경을
확인할 수 있다. 목도 분야·모집 상태 필터와 정렬을 적용한 다음 페이지를 나눈다. 마감 임박순은 모집 중 날짜순,
날짜 없는 모집, 지난 마감순이며, 지난 마감은 최근 날짜부터 표시한다. 같은 마감일은 원문 작성 최신순·ID 내림차순이다.

## 배우 지원

| 시나리오 | 경로 | 확인 내용 |
| --- | --- | --- |
| 기본 복수 배역 | `/apply/seed_posting_1` | 복수 배역, 기본·추가·사진·영상·질문·검토 단계 |
| 최소 정보 | `/apply/seed_posting_minimal` | 단일 배역 선택 생략, 빈 섹션 생략 |
| 키 미수집 | `/apply/seed_posting_without_height` | HEIGHT 미노출, WEIGHT 필수 |
| 전체 항목 | `/apply/seed_posting_all_fields` | 전체 기본·추가 정보와 긴 질문 |

사진 보관함은 지원서에 자동 첨부하지 않는다. 보관함 선택과 새 파일은 요구 슬롯 단위로 Draft에 저장한다.
실제 UUID 공고 제출은 MSW 환경에서도 백엔드 세션과 `/api/v1/**` 제출 계약을 사용한다.

OTR 공고는 목 공연사 화면에서 새 공고를 만들면 `/apply/standard/{id}` 링크가 생긴다. 목 공개 조회는
한국 시간 날짜로 마감 여부를 계산하고, 배역 1개·기본 정보 전체·사진 파일 ID와 영상 URL 각각 0~3개·두 동의를
검사한다. 미디어 목록은 생략할 수 있다. 목 상태는 메모리 기반이며 새로고침하면 초기화된다.
OTR 공고 목록의 심사 관리에서 배역을 선택하면 접수된 지원서가 기존 심사 화면에 표시된다. 목 심사 결과와
배역별 마감도 같은 메모리 상태를 사용하며, 지원 마감 다음 날부터 심사를 종료할 수 있다.

## 문자 화면

`seed_*` 배역의 `/sms-*`는 목 미리보기·발송 내역으로 처리하고 실제 숫자 배역은 passthrough한다.
OTR `/sms-*`는 producer API 활성화 시 passthrough하고, 목 모드에서는 OTR 심사와 같은 메모리의 PASS 지원자를
사용한다. 공고 UUID·배역 순번별로 내역을 분리하고 내역이 없으면 정상 빈 배열을 반환한다.
초안 API의 메모리 handler는 호환성을 위해 유지하지만 현재 문자 작성 화면에서는 호출하지 않는다.
목 화면에는 실제 발송·과금이 아니라는 안내를 표시한다. 모든 문구를 LMS 30원으로 가정한 화면 fixture이며
실제 인코딩·과금 검증이 아니다. 수신자 순서대로 DELIVERED / FAILED / UNKNOWN을 반복해 부분 결과를 확인한다.
문구에 `[잔액부족]`을 넣으면 목 오류가 반환된다. 새로고침 시 메모리 상태는 초기화된다.
목 재발송은 지원하지 않는다. 재발송·중복 방지·실제 HTTP 계약은 백엔드 Fake 통합 테스트에서 검증한다.

## 공통 검증

- 모바일 390×844와 데스크톱 1440×1000에서 가로 overflow가 없어야 한다.
- sticky header와 하단 action이 내용을 가리지 않아야 한다.
- 키보드로 단계 이동, 필터와 결과 버튼을 사용할 수 있어야 한다.
- 필수·선택·잠김·검토 대기·완료 상태는 텍스트로도 구분한다.
- 로딩·빈 상태·오류 상태에 접근 가능한 이름과 복구 안내를 제공한다.

목 배우(김하린)의 페이지 설정은 지원자 목 저장소의 프로필·사진·영상을 그대로 읽는다. 목에는 공개 사본이 없어 원본 주소를
사본 대신 붙이고, 공개하면 `/actors`와 `/actors/@아이디` 목에도 맨 앞에 보인다. 아이디 `min.zzun_` 등 고정 배우의 아이디와
`hidden.actor`는 사용 중으로 답한다. 주소의 `mockActorPage=public|locked|unlocked|auto-hidden`은 그 페이지에서 처음 나가는
API 요청 때 시작 상태를 바꾼다. 서버는 저장할 때 자동 비공개로 바꾸지만 목은 다음에 설정을 읽을 때 맞춘다.
새로고침하면 처음 상태로 돌아간다. 설정 탭의 '내 페이지 열기'는 새 창이라 목 상태도 처음으로 돌아가므로 공개된 목 배우의
페이지는 `/actors/@harin.kim?mockActorPage=public`으로 연다. 목에서는 서버 렌더링 대신 브라우저가 다시 읽으므로 대문자 주소는 서버의 308 대신
브라우저에서 주소만 바꾼다.

관심 배우 목은 공개 배우 2명과 비공개가 된 배우 1명을 저장해 둔 상태로 시작한다. 목 로그인 세션은 메모리에만 있어 새로고침하면
풀리므로 대시보드의 '배우 둘러보기'와 카드 링크로 이동한다. 한도 안내는 `/actors?mockActorBookmarks=full`처럼 주소에 붙이면
그 페이지의 첫 관심 배우 요청 때 숨긴 저장 298명을 채워 300명이 된다(같은 탭에서 앱 안 이동으로 열어야 로그인이 유지된다).

PDF로 채우기 목은 올린 파일 내용과 상관없이 같은 결과(김하린, 키 167cm, 경력 4개, 사진 후보 2장)를 준다. 결과가 처음 보이면
오늘 횟수를 쓴 것으로 바꾸고, 읽지 못한 결과는 세지 않는다. 목 보관함은 사진 3장으로 차 있어 후보를 넣으려면 사진 탭에서
한 장을 지운다. 넣은 후보 사진은 지원자 목 보관함에 더해지고, 새로고침하면 모두 처음으로 돌아간다.

운영자 배우 페이지 API 목은 공개 배우 14명과 비공개 배우 1명을 대상으로 한다. 잠금·해제·아이디 변경은 공개 목록·상세와
같은 메모리를 사용하고 새로고침하면 초기화된다. 잠금 해제 뒤에는 비공개로 남는다. 변경은 운영자 변경 기록 목에도 쌓이며,
연락처 열람·같은 아이디로 변경·이미 풀린 잠금 해제는 기록하지 않는다. 고정 배우 목과 배우 본인 설정 목은 별도 상태다.
운영 화면의 서버 접근 검사는 브라우저 MSW 세션을 읽지 못하므로 위 UI 시나리오는 실제 운영자 세션과 API로 확인한다.
API 목의 잠금·아이디 변경·공개 화면 반영은 `src/mocks/actor-page-handlers.test.ts`에서도 확인한다.

## 운영 대시보드

운영 화면은 `/login`의 기획사/제작사 폼에서 실제 운영자 계정으로 로그인한 뒤 연다. 서버 접근 검사가 있어 브라우저 MSW의
목 세션만으로 `/admin`을 열면 404다. 세션 API 목 자체는 `admin@`으로 시작하는 이메일을 ADMIN으로, 다른 이메일은
기획사로 처리하며 운영 API 목은 기획사 세션에 `403`을 반환한다. 개요·회원·기획사·오디션·무료 공연·변경 기록은 `?tab=`으로 열고 로그는
`/admin/logs`다. 목은 기획사 3곳(인증 대기 1), 공고 4건, 운영자 변경 기록 2건, 고정 패턴의 최근 14일 활동과 가입 경로를 두고,
무료 공연 예매 집계는 무료 공연 목과 같은 메모리 상태에서 계산해 관객 예매·기획사 취소가 바로 반영된다. 수동 활성화는
변경 기록을 추가하고, 지원서 삭제는 확인 비밀번호가 비어 있지 않으면 성공한다. 지원서 상세는 목에서 제공하지 않는다.
`NEXT_PUBLIC_PRODUCER_LOGIN=enabled`면 세션이 실제 백엔드에 있으므로 운영 API도 실제 백엔드로 넘긴다.
무료 공연 탭의 "주최(관객 화면)" 칸에서 공연마다 주최 이름을 고칠 수 있다. 비우면 계정 기획사명으로 돌아가고, 변경 기록에
`SHOW_HOST_NAME_CHANGED`가 이름 없이 쌓인다. "외부 링크 공연 등록"으로 기획사 계정 없는 공연을 등록하고(주최·외부 예매 링크
필수, 주소 검색은 카카오 팝업), 운영자 공연명(`숲속 버스킹 연극` 등)을 누르면 `/admin/shows/{showId}`에서 기획사 관리 화면과 같은
화면으로 회차(시작 일시만)·공개·마감·정보 수정을 한다. 표와 관리 화면에 예매하기 이동 횟수가 보인다(시드 12회).
운영자 공연은 기획사 목 API에서 보이지 않는다. 목은 운영자 공연 변경 기록을 쌓지 않고,
무료 공연 목과 같은 메모리를 쓰므로 새로고침하면 초기화된다.

## 운영 로그

MSW에서는 `/api/v1/admin/logs`에 정상 HTTP, 1초 이상 느린 HTTP, 예상 밖 ERROR와 기존 `LEGACY` 로그를 함께 반환한다.
`/api/v1/admin/files/unreferenced` 조회와 단건·일괄 삭제는 실제 관리자 API로 전달한다.
`/admin/logs`에서 6개 요약 필드, ERROR·WARN·INFO·DEBUG·TRACE 레벨 필터, 느린 요청 필터, request ID·키워드 검색과 stack trace 펼침을 확인한다.
날짜에서 지난 날짜를 고르면 목은 INFO 로그만 돌려주고, 자동 새로고침이 꺼진다. 목은 날짜별로 다른 로그를 두지 않는다.

공연 관리의 `공연 숨기기`는 관객 목록·상세·예매·외부 이동 기록에서 제외하며, `숨김 해제`는 예매 상태를 유지한다.
기획사·관리자 `PATCH .../shows/{id}/visibility`의 필수 boolean `hidden`과 초안 거절을 실제 API와 동일하게 모사한다.
